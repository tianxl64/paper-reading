World4Drive：Intention-aware Physical Latent World Model

Academic 风格深度精读｜论文版本：arXiv:2507.00603｜源码：ucaszyp/World4Drive（master 归档）｜报告日期：2026-09-01

意图感知物理潜变量多模态规划世界模型选择器源码解剖

一句话结论：World4Drive 不把世界模型当作“生成视频”的附属模块，而是让每个驾驶意图先产生一条候选轨迹，再把“这条轨迹会导致什么未来潜在世界”预测出来；训练时用真实未来潜变量挑选最可信模态，推理时由 ScoreNet 直接选分最高的轨迹。

证据范围：论文 TeX 全文（方法、实验、结论）、官方源码归档、配置文件与关键模块实现。源码解释采用“功能—数据形状—训练作用—潜在陷阱”方式，不堆砌代码。

1. 阅读地图：从论文主张到可执行代码

论文机制链

多视角 RGB → 图像特征 → 语义伪标签与 metric depth → 3D 空间编码 → 时间聚合潜变量 Lt → 意图查询 → 3×6 候选轨迹 → 轨迹动作 token → 未来潜变量 → latent 距离选择器 → 规划轨迹。

代码真实链

W4D.forward_train 先切历史队列与当前帧；SimpleWayDecoderHead.forward 完成位置、时间、轨迹、世界模型预测；W4D.forward_pts_train 逐模态计算重建/KL/cosine 距离并选最优模态，再回传轨迹与世界模型损失。

2. 为什么需要 Intention-aware World Model

单一未来预测在驾驶场景中天然含糊：路口既可能左转，也可能直行；同一视觉观测下，未来不是一个点而是一组受驾驶意图约束的分支。论文的关键判断是：先显式枚举意图，再让世界模型评估每个意图对应的未来状态，比直接让一个 decoder 平均多个未来更可解释，也更容易与轨迹规划连接。

2.1 创新点拆解

  1. 意图编码器：从 trajectory vocabulary 的终点做 k-means，形成左/直/右三类、每类 6 个 intention prototypes。
  2. 物理潜变量：不是只取 camera feature，而是用 Grounded-SAM 的语义监督、metric depth 的尺度深度和 forward projection 的 3D 位置编码，形成空间—语义—时间联合表征。
  3. Dreamer：每个候选动作 token 都驱动独立未来潜变量预测，形成“轨迹—未来世界”配对。
  4. Selector：训练时拿预测潜变量与真实未来潜变量比距离，自动产生 best modality；推理时使用 ScoreNet 的最高分。

图2｜意图编码器：k-means 终点原型与多模态规划查询

全部细节：图2专门解释意图不是一个简单三分类。轨迹词表 V 的每条样本含 S=6 个 waypoint，但 k-means 只读取最后 endpoint；先按左转、直行、右转 command 分组，再在每组内聚 K=6 个中心，因此总数是18而非6。终点 [B,3,6,2] 经过正弦位置编码和 embedding 变为 [B,3,6,256]，flatten 成 [B,18,256]，再与扩展后的 learnable ego query 和 ego 原点编码相加。ego self-attention 让不同候选交换信息，输出 Qplan。路口小例子说明同一 command 内的6个模式可以覆盖不同曲率、终点和速度，而不是六个重复标签；源码锚点是 kmeans_plan_6.npy 与 forward 中372–390行。

图3｜物理潜变量：语义、尺度深度与 forward 3D 投影

全部细节：图3把“物理”拆成可追踪的三类信息。语义分支由 Grounded-SAM 根据对象 prompt 产生高置信伪 mask，低置信标签被过滤，17类 semantic head 通过交叉熵监督 latent；它是训练先验，不是部署时人工标注输入。几何分支由 Metric3D v2 输出有真实尺度的深度，齐次像素 [u,v,1] 经 K−1、深度乘法和相机到 ego 变换得到 p={x,y,z}，构成 Pt。SPE+MLP 把三维位置编码为 D=256 的 Et，与 Ft 相加。六个独立 temporal decoder 再将 current query 与 previous memory 聚合；首帧 memory 为零，输出 detach 后存入 prev_view_feat。最终 Lt 的240个 token同时携带距离尺度、对象语义与跨帧运动。

图4｜时间聚合与源码真实状态：prev_view_feat 的跨帧缓存

全部细节：图4逐步复原真实执行状态。输入张量 [B,4,6,C,H,W] 被明确拆成三帧 prev_img 和一帧 cur_img，depth 以同样边界切分；历史帧在 obtain_history_feat 中按时间顺序处理。序列入口先把 prev_view_feat 设为 None，head 首帧据此建立 zeros_like memory。每个相机拥有独立三层 TransformerDecoder，current spatial_view_feat 是 query，上一帧缓存是 memory，不能反画。final_view_feat 通过 detach 写回，含义是保留状态但截断跨时间反向图。最后历史帧生成的 prev_pred_img_feat 与当前 cur_img_feat.detach() 对齐，构成世界模型监督。右下风险框强调训练和测试都必须在新序列开始清零，否则模块状态会跨样本污染。

图5｜规划头：18 个 query 如何变成 3×6 条 6-waypoint 轨迹

全部细节：图5解释规划头的每次 reshape。kmeans_plan_6.npy 提供 [3,6,6,2] 的参考轨迹，batch 扩展后为 [B,3,6,6,2]；只取终点做 sine embedding，得到18个256维 token。单个 learnable waypoint query 被广播到18份，加上意图和 ego 原点编码后进入一层 ego_attn。三层 wp_attn 以18个规划 token为 query，以 [B,6,240,256] 的多视角物理 latent 为 memory。输出重排回 [B,3,6,256]，回归头产生12维即六个二维增量，最终是 [B,3,6,6,2]；分类头给 [B,3,6]。图中特别画出 cumsum(-2)：世界模型接收的是累计空间轨迹，而非互不关联的增量点。

图6｜Dreamer：动作 token 驱动 18 个未来潜变量

全部细节：图6是第二张源码专项图。对当前 command 的每个 mode k，累计轨迹 [B,6,2] 被编码为动作条件；每个相机 view 又有240个独立 Qfuture 槽位。_wm_decoder[i] 以这些未来 query 为 query，以当前 view latent 与动作 token 的组合为 memory，循环六个 view 后得到单模态 [B,6 views,240,256]。外层再循环六个 mode，stack 成 [B,6 modes,6 views,240,256]；两个“6”分别是轨迹模式和相机视角，不能混淆。对 view 和 token 维做均值池化形成 [B,6,256]，再由 ScoreNet 输出每模态分数。训练侧的 MSE、KL、cosine 与 diversity 只监督 latent；模型预测的是压缩世界状态而不是 RGB 视频。

图7｜Selector：训练期 latent 距离匹配与推理期 score 选择

全部细节：图7严格分隔训练 oracle 与部署路径。训练时，真实未来图像经同一编码器得到 L̂t+n，六个预测 latent 分别计算 MSE reconstruction、KL 和 cosine，源码把三项相加得到 dk。select_optimal_modality 还支持 FDE 项，但 W4D.py 当前主调用明确传入 weight_tm=0.0，因此正式选择由 latent 距离决定。argmin 得到 j 后，一方面选中对应 latent/轨迹计算重建与 waypoint loss，另一方面把 j 当作 ScoreNet 的 focal-loss 标签；它不是人工左/直/右标签。推理时真实未来帧、oracle latent 和距离计算全部消失，只执行 ScoreNet(Lk) 与 argmax。图中示例距离只用于解释 argmin，不是论文实验数据。

图8｜端到端训练/推理完整数据流与损失回传

全部细节：图8把源码执行顺序和所有损失放进一张闭环图。数据端包括六路RGB、depth、semantic mask和ego轨迹，queue_length=4；forward_train 先历史后当前，head 依次完成三维位置、语义、时间、18-query规划和未来 latent。训练损失包括 reconstruction/MSE、KL、cosine、cosine_thre=0.7 的 diversity、semantic CE、ScoreNet focal、waypoint L1/Focal。模态选择仍使用 weight_tm=0.0 的 latent argmin。论文公式给 α=.2、β=.2、γ=.5、η=1.0，而源码显式出现 wm_loss_weight=.2、semantic_loss_weight=.05，并附加多种 latent 与历史项，复现必须以实际 loss 字典为准。推理支路删除未来真值，只保留 ScoreNet argmax。评测区分 nuScenes 开环 0.50m/0.16% 与 NavSim 闭环 PDMS=85.1，二者不能混用。

4. 关键公式与直观解释

4.1 意图查询

Qplan = SelfAttention(Qego + QI)

把“我车当前要做什么”和“候选意图的空间终点”放进同一个 token 集合。Self-attention 允许左转 query 与直行 query 互相看到，但不会把它们平均成单一路径。

4.2 3D 位置与时间

Et = MLP(SPE(Pt)),　F̂t=Ft+Et,　Lt=CrossAttention(F̂t,F̂t−1)

depth 让同样的像素坐标在远近尺度上可区分；forward projection 把图像网格变成 ego 坐标中的几何点；时间 cross-attention 让 latent 能利用运动线索，而非只记住静态纹理。

4.3 意图条件世界模型

T = MLP(CrossAttention(Qplan,Lt)),　Lt+n=CrossAttention(Qfuture,Concat(A,L))

第一式把场景 context 注入意图 query 并生成轨迹；第二式把每条轨迹编码为 action token，再和当前 latent 拼接，预测该动作下的未来世界。

4.4 选择器的训练—推理错位

j = argmink d(Lt+nk, L̂t+n),　S=Softmax(C(Lt+n))

训练期的真实未来 latent 是“oracle”证据，只用于挑选 j 与监督 ScoreNet；推理期没有未来帧，所以依赖已学会的 S。这个结构把不可用的未来信息转化成训练标签，避免部署时偷看未来。

5. 源码精读：从类、函数到张量

5.1 顶层时序切分

W4D.forward_train（projects/mmdet3d_plugin/W4D/W4D.py:137）接收 queue。配置 queue_length=4（projects/configs/w4d/default.py:44），代码将前三帧送进 obtain_history_feat，当前帧单独编码。关键点不是“用了历史”，而是历史预测出的 future latent 被拿来与当前观察 latent 对齐，形成可监督的世界模型学习信号。

prev_img = img[:, :-1, ...] cur_img = img[:, -1, ...] prev_frame_losses, pred_img_feat, ... = self.obtain_history_feat(prev_img, ...) cur_img_feats = self.extract_feat(img=cur_img, ...)[0] losses = self.forward_pts_train(cur_img_feats, pred_img_feat=pred_img_feat, ...)

5.2 空间位置与 temporal decoder

waypoint_query_decoder_simple.py:281-318 的 img_position_embeding 通过 depth 和相机变换得到 3D 坐标，再归一化后过 MLP。:361-368 的时间缓存为每视角一个 decoder；首帧用零 memory，输出 detach 后作为下一次 memory。这种实现将跨帧梯度截断，控制显存与训练稳定性。

5.3 多模态轨迹与世界模型预测

:372-414 先把 waypoint_mode_ref 扩成 [B,3,6,6,2]，构造 18 个 mode query；经过 ego self-attention 与 view feature cross-attention 后输出轨迹。然后对每个 trajectory modality 调用 wm_prediction（:543-552），得到每个 view 的 240 spatial tokens；堆叠结果为 [B,6,6,240,256]，平均成 [B,6,256] 的分数特征。

5.4 选择器为何是“自监督标签制造器”

W4D.forward_pts_train（:245-297）为每个模态分别计算 reconstruction、KL 与 cosine；select_optimal_modality（waypoint_query_decoder_simple.py:587-608）再把 latent 距离与小权重 FDE 合并，argmin 得 best_modality_idx。随后 loss_wm_cls 用 focal loss 学习这个 index。源码注释明确了设计意图：不是用人工 command 直接选，而是用“哪个未来 latent 最像真实世界”来选。

6. 一个浅显例子：路口左转还是直行

假设当前相机看到十字路口，导航允许左转或直行。意图编码器生成两组 query：左转组会把终点 prototype 放在左前方，直行组放在正前方。规划头分别给出 6 个左转轨迹与 6 个直行轨迹。Dreamer 对每条轨迹问一句：“如果我按这条轨迹走，3 个时间间隔后世界 latent 应该长什么样？”真实未来帧到来后，selector 发现“左转第 2 模态”的 latent 与真实场景最接近，于是训练时把 index=2 当成 ScoreNet 标签；部署时没有真实未来，就让 ScoreNet 根据当前 latent 预测最高分模态。

关键直觉：轨迹不是单独打分，而是通过它将世界推进到哪个未来状态来打分。这样“合理”不仅意味着几何上像专家轨迹，还意味着它对场景变化的预测也可信。

7. 实验与消融：应该怎样读

论文在 nuScenes 与 NavSim 上报告端到端规划结果，并分析各组件、驾驶条件、maneuver 与 world model scalability。阅读实验时重点关注三类证据：

  1. 组件增益：去掉意图编码、物理潜变量或 selector，性能下降说明收益来自完整闭环，而非单一 decoder。
  2. 条件鲁棒性：不同天气/光照/交通密度下的结果能检验语义与几何先验是否真的改善可迁移性。
  3. 规模性：改变候选模态或 world-model token 数量，观察计算量与规划收益的折中。

7.1 已核录的代表性结果

nuScenes 3 秒、2Hz 开环规划中，World4Drive 的平均 L2 为 0.50 m，平均碰撞率为 0.16%；对应 1/2/3 秒 L2 为 0.23/0.47/0.81 m，碰撞率为 0.02/0.12/0.33%。相较 perception-free LAW* 的 0.61 m 与 0.30%，说明 latent world selector 主要改善的是长期轨迹与安全性，而不是只优化短期点误差。

在 maneuver 分解中，World4Drive 的左/右/直行 L2 为 0.63/0.69/0.48 m，碰撞率为 0.40/0.20/0.14%；全体仍为 0.50 m 与 0.16%。论文还报告在夜间和雨天相对 LAW 的碰撞率分别下降 63.7% 与 68.8%，这正是语义与尺度几何先验可能发挥作用的条件。

NavSim 是闭环 PDM 评测：轨迹按 2Hz 预测 4 秒，再用 LQR 插值控制；指标包含 NC、DAC、TTC、Comfort、EP 与 PDMS。图8若绘制实验侧，必须把“nuScenes 开环 L2/CR”和“NavSim 闭环 PDMS”画成两条独立评测链。

8. 局限、风险与复现注意事项

  • Grounded-SAM 伪标签的错误会通过 semantic loss 进入 latent；高置信筛选降低噪声但不能消除开放词汇偏差。
  • metric depth 是强先验；深度尺度或相机标定错误会直接污染 3D positional embedding。
  • 训练期 selector 使用真实未来 latent，存在 teacher/oracle gap；ScoreNet 的泛化决定部署可靠性。
  • 代码中 prev_view_feat 是模块状态，测试/多 batch 场景必须确认每个序列开始前被清零，避免跨样本污染。
  • 源码默认配置的命名和论文权重并不完全一致，复现时必须以 config 与实际 loss 汇总为准。
