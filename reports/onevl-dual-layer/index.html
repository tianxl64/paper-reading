0. 先给结论：OneVL 真正在改什么

OneVL 不是把已有 VLM 接一个轨迹头那么简单。它把显式推理链拆成两类 latent token：视觉 latent 承担未来场景动力学，语言 latent 承担可读 CoT 的压缩表征。训练时两个 auxiliary decoder 都在场，分别把 latent hidden states 还原为未来视觉 token 和文字推理；推理时两个 decoder 都被丢弃，只把 latent token 预填到 prompt 中，主模型并行吃掉这些 token 后直接生成轨迹答案。

这使论文的核心 claim 变成一个可审计的三段式：第一，普通 latent CoT 在驾驶上失败，因为缺少任务相关监督；第二，世界模型式视觉监督和语言解释监督能把 latent 从“黑箱压缩槽”变成“可被解码的驾驶状态”；第三，prefill 让这些 latent 不参与逐 token 自回归，因此延迟约等于 answer-only。

1. 研究问题：latent CoT 在驾驶里为什么原本不够用

论文把问题定位在 VLA 自动驾驶的一个矛盾上：显式 CoT 可解释但慢，answer-only 快但缺少中间监督，通用 latent CoT 本该快，却在驾驶任务中低于 answer-only 甚至显著低于显式 CoT。NAVSIM 表里 COCONUT、CODI、SIM-CoT 的 PDM 分别是 84.84、83.92、84.21，全部低于 AR Answer 的 87.47，这说明“把语言推理压进 latent”这个通用技巧直接迁移到轨迹预测并不成立。

OneVL 对这个失败给出的解释是 supervision mismatch：驾驶规划不是纯语言推理题，latent token 如果只从最终轨迹损失或一般语言压缩中学习，很容易变成不可解释的瓶颈；它缺少与场景未来状态绑定的监督。因此 OneVL 用未来帧视觉 token 预测提供密集世界模型信号，用 CoT 文本重构提供语言解释信号。

2. 方法机制：两个 latent 通道不是装饰

OneVL 的输入是图像和结构化驾驶文本，输出序列中被插入视觉 latent token、语言 latent token 和轨迹 answer token。主 VLM 产生这些位置上的 hidden states 后，视觉 latent 的 hidden states 送入视觉辅助 decoder，语言 latent 的 hidden states 送入语言辅助 decoder。注意这里不是把 decoder 输出作为最终答案的一部分，而是把 decoder 当作训练时的可解释监督器。

架构图里下方的 hidden state 路由是读懂 OneVL 的关键：H_v 和 H_l 都来自主 VLM，但监督目标不同。视觉分支绑定 t+0.5s/t+1.0s 未来帧 token；语言分支绑定 CoT 文本。

机制深挖：为什么视觉 decoder 比语言 decoder 更像关键部件

消融里去掉视觉 decoder 后 PDM 从 88.84 降到 87.97，去掉语言 decoder 后降到 88.53。二者都有效，但视觉 decoder 的影响更大。原因很直接：自动驾驶轨迹预测的核心不只是解释为什么转弯，而是判断未来空间可通行性、动态障碍和道路拓扑演化。视觉 token 预测比文字 CoT 更接近这些状态变量。语言 decoder 的主要价值是让 latent 可读、可审查，并通过文本 CoT 给模型一个更稳定的语义分解目标。

机制深挖：prefill 不是减少 token 数这么简单

显式 CoT 慢，是因为中间推理文本要自回归生成，每个 token 都依赖前一个 token。OneVL 的 latent token 虽然也出现在序列中，但它们在推理时被直接预填为固定 token 块，模型只需要并行计算它们对应的 hidden states，再自回归生成轨迹 answer。因此延迟主要取决于最终 answer token，而不是 reasoning token 长度。

3. 数学与算法重构：从三个交叉熵到一个训练目标

论文的数学不复杂，但容易被误读成“多任务 loss 堆叠”。更准确地说，它定义了三个不同层级的监督：主轨迹答案损失 L_c 保证规划输出；语言辅助损失 L_l 迫使语言 latent 能还原 CoT；视觉辅助损失 L_v 迫使视觉 latent 能预测未来帧 token。总损失是加权和，其中 lambda_l=1.0，lambda_v=0.1。

L = L_c + lambda_l L_l + lambda_v L_v, lambda_l = 1.0, lambda_v = 0.1

独立推导可以从最大似然出发：如果主答案、语言 CoT、未来视觉 token 被视为三个条件生成目标，那么联合训练的负对数似然可以分解为三项条件交叉熵。论文并没有声称三项目标独立，只是在优化上用线性加权近似多目标训练。这个推导能解释为什么 lambda_v 小于 1：视觉 token 序列长且来自离散 tokenizer，如果权重过大，模型会优先优化未来帧 token 复原而不是规划。

核心公式独立推导

前提 1：主 VLM 看到输入 x 和 latent prompt 后生成轨迹答案 y，最大化 P(y|x,z)。前提 2：语言辅助 decoder 看到语言 latent 表征 z_l 后生成 CoT token 序列 c。前提 3：视觉辅助 decoder 看到视觉 latent 表征 z_v 后生成未来视觉 token 序列 v。

- log P(y,c,v | x,z) approx L_c + lambda_l L_l + lambda_v L_v

若把三项目标写成 token 级条件概率，L_l 和 L_v 都是 teacher-forcing 交叉熵：每一步预测当前 token，条件包括 latent 表征和之前的目标 token。论文省略的步骤是从 token 序列概率分解到求和形式，即 P(c|z_l)=prod_i P(c_i|z_l,c_{<i})。这一步是标准自回归分解，没有额外理论技巧。

推导限制：该 loss 并不保证 latent 形成因果世界模型，也不保证未来视觉 token 与真实物理状态一一对应。它只证明训练信号鼓励 latent 包含足够信息以被 decoder 还原。是否形成可泛化的驾驶表征，需要靠 ablation 和跨 benchmark 结果验证。

4. 训练拓扑：Stage 不是小细节，而是成败条件

论文训练流程包含 preliminary visual decoder pretraining、Stage 0 主 VLM warmup、Stage 1 冻结主模型只训练辅助 decoder、Stage 2 联合 fine-tuning。这个顺序背后的工程逻辑是防止辅助 decoder 在主模型尚未稳定时牵引 backbone，或者在 decoder 尚未学会解码时用噪声监督破坏 latent。

反驳视角：为什么不能只看 88.84

第一，OneVL 的显式语言解释质量平均分 76.13，低于 AR CoT 的 78.27。它恢复了大部分解释能力，但不是完全等价。

第二，NAVSIM 的 PDM-score 是 non-reactive planning benchmark，无法覆盖交互闭环、对抗车辆和真实执行器噪声。

第三，MLP head 把延迟降到 0.24s 但 PDM 降到 86.83。如果产品目标是实时部署，不能直接拿 full AR OneVL 的 88.84 当部署性能。

8. 局限、失败条件与更强基线

OneVL 的最大局限是它把“可解释 latent”定义为可被辅助 decoder 还原，而不是人类可直接检验 latent 的因果含义。视觉 decoder 能生成未来帧 token，不代表 latent 内部按物理状态变量分解；语言 decoder 能生成 CoT，不代表轨迹决策真正依赖这些文字因果链。

三个理论反驳

反驳 1：如果未来视觉 token 的预测质量与规划目标弱相关，那么视觉 auxiliary decoder 只是在学 reconstruction，而不是驾驶动力学。移除的假设是“未来视觉 token 是规划充分统计量”。

反驳 2：如果 CoT 文本本身来自模板化标注或弱 teacher，那么语言 auxiliary decoder 可能只学到解释风格，不学到可迁移 reasoning。移除的假设是“文字 CoT 含有真实决策因果结构”。

反驳 3：如果 benchmark 的 latency 主要由输出长度控制，那么 OneVL 的速度优势可能来自 answer 格式短，而不是 latent 本身更优。需要对相同 answer 格式、相同 decoding budget 做硬件一致性测量。

9. 逐模块深读：把 OneVL 当作一个训练约束系统，而不是单个模型

9.1 Latent token interface 的真实约束

OneVL 的 latent token interface 有一个容易被忽略的工程选择：它没有新增不可见的连续变量，而是使用现有 vocabulary 里的标记块来定位 latent 区间。这样做的收益是推理代码可以保持标准 VLM token 流，checkpoint 与 tokenizer 的兼容性更高；代价是 latent 的表达能力并不是“无限连续记忆槽”，而是由这些 token 位置上的 hidden states 承担。换句话说，token 本身只是定位符，真正被监督的是该位置经过 VLM 计算后的 hidden state。

这也解释了为什么代码里要专门做 latent position detection。`infer_onevl.py:170-177` 不是普通字符串处理，而是在原始 vocabulary token 序列里定位 visual/text latent block 的精确位置。辅助 decoder 需要从这些位置抽取 hidden state；如果 tokenization 变动、特殊标记被拆分、或 prompt 模板和训练不一致，decoder 读到的 hidden state 就会偏移。这是复现时很容易出错的隐藏依赖。

从表征学习角度看，OneVL 的 latent token 像一个被多重约束的 bottleneck：主轨迹损失要求它对 answer 有用，语言 decoder 要求它能还原文字 reasoning，视觉 decoder 要求它能还原未来场景 token。这个 bottleneck 的价值不在于压缩本身，而在于压缩目标被任务化了。COCONUT/CODI/SIM-CoT 在驾驶上低于 AR Answer，说明“压缩推理链”这个抽象目标不足以产生驾驶可用 latent；OneVL 的关键是让压缩对象变成未来视觉和驾驶解释。

9.2 视觉辅助 decoder 的世界模型边界

视觉辅助 decoder 预测的是未来帧的 visual token，而不是显式 3D occupancy、BEV flow 或 agent trajectories。因此它更准确的名字是 weak visual world-model supervision，而不是完整 world model planner。它通过 Emu3.5/IBQ 这样的离散视觉 token space，把未来图像压成可预测的离散序列，使 VLM hidden states 被迫携带未来场景外观、道路结构和动态对象线索。

这种设计的优点是监督密度高：单条样本的未来帧 token 比最终轨迹坐标提供更多局部视觉约束。它还绕开了显式建模所有交通体状态的复杂标注需求。缺点同样明显：future image token 对规划是否充分没有理论保证。视觉 token 可能主要重构纹理、光照或背景，而不是影响轨迹的关键对象；如果 tokenizer 对小目标或交通灯状态不敏感，视觉辅助监督也会丢失这些决策变量。

论文用 Fig. ablation_visual_cot 试图支撑视觉 decoder 的有效性：完整训练下未来帧保持场景一致，错误训练下出现记忆化伪影。这个证据说明 staged training 能避免 decoder 过拟合，但还不能证明 decoder 生成的是规划因果状态。更强验证应当做反事实：遮挡一个关键障碍物、改变红绿灯或施工锥桶，再观察 visual latent 解码和轨迹是否同步变化。

9.3 语言辅助 decoder 的解释性边界

语言辅助 decoder 把 language latent hidden states 解码回 CoT 文本，它给 OneVL 带来两层价值。第一层是训练价值：让 latent 学到与显式 reasoning 文本相关的语义结构。第二层是审计价值：推理后可以打开 decoder 生成文字解释，帮助人检查模型为什么给出该轨迹。

但这两层价值不等同于因果解释。语言 decoder 的输出是从 latent 重构出来的文本，它可能是 post-hoc rationalization，而非真正决定轨迹的因果链。论文的 explanation quality 表显示 OneVL avg 76.13，接近但低于 AR CoT 的 78.27；这说明它恢复了大部分可读性，但仍存在语义细节损失。尤其在安全关键场景，解释稍弱可能意味着漏掉关键危险对象、优先级判断或交通规则描述。

因此这份报告建议把 OneVL 的语言解释看作“latent 可读性 probe”，而不是“安全证明”。如果用于工程诊断，可以比较 language aux decoder 的解释与 visual aux decoder 的未来帧是否一致：文字说前方施工需要绕行，视觉 token 解码是否也显示施工区域；文字说保持车道，预测轨迹是否真的不越线。三者一致时解释更可信，不一致时应优先暴露给 reviewer。

9.4 MLP deployment head 的取舍

OneVL 论文和 README 都强调 full AR OneVL 在 NAVSIM 达到 88.84 PDM / 4.46s，而 MLP head 变体达到 86.83 PDM / 0.24s。这个结果对产品部署非常重要，因为它把 OneVL 分成两个模式：研究模式用 autoregressive answer 追求最高分并保留更完整解释；部署模式用 latent hidden state 接 MLP 直接回归 waypoints，把延迟压到实时系统更可接受的范围。

这不是免费午餐。MLP head 比 full AR 少了 2.01 PDM，说明自回归答案仍携带有用的序列建模能力。若部署目标是高速闭环控制，0.24s 可能比 88.84 的离线分数更有价值；若目标是 benchmark SOTA 或离线规划，full AR 更强。工程上不能简单说 OneVL 延迟就是 4.46s 或 0.24s，而要明确使用哪个 head、是否启用解释 decoder、是否跑 visual decoding 后处理。

代码也支持这个分歧：`infer_onevl.py:636-643` 的 float_head_type 只支持 mlp，并明确 flow-matching head unsupported；`scripts/infer_navsim_mlp.sh:37-51` 仍保留 language/visual explanation toggles。这意味着低延迟部署和解释生成可以组合，但解释生成本身会增加额外计算，不应混入主轨迹 latency 统计。

10. 实验读法：从结果表反推作者的论证链

10.1 NAVSIM 不是唯一证据，但它是最关键证据

NAVSIM 表承担了论文最强的 claim：OneVL 是 latent CoT 中唯一同时超过 AR CoT 和 answer-only 的方法。这个 claim 之所以有力度，是因为作者把三类基线放在同一张表：已有 VLA/自适应思考方法、Qwen3-VL 4B 下的 AR Answer/AR CoT、以及通用 latent CoT 方法。这样可以排除两个简单解释：不是因为模型更大，也不是因为只比较了弱 baseline。

不过 NAVSIM 的限制也必须同时读出来。它是 data-driven non-reactive benchmark，指标 PDM 关注规划轨迹与规则/舒适性等综合评分，但场景不会因为 ego 动作产生新的交互反馈。OneVL 在这里的优势说明它学到了更好的离线规划表示；它不直接说明模型在真实交通互动中能处理抢行、礼让、插队或多车博弈。

最值得注意的是 AR Answer 87.47 / 4.49s 与 OneVL 88.84 / 4.46s 的对比。二者延迟几乎相同，但 OneVL 高 1.37 PDM。这是 prefill latent 的核心证据：latent token 不带来显式 CoT 的自回归延迟，却能提供类似中间推理的表征收益。如果只看 OneVL vs AR CoT 的速度差，容易误以为优势来自少生成文本；OneVL vs AR Answer 才真正说明 latent prefill 增加了有效信息。

10.2 ROADWork 和 Impromptu 验证的是分布外韧性

ROADWork 关注施工区，场景包含临时锥桶、路障、工区改道等普通自动驾驶数据中较少出现的结构。OneVL 在 ROADWork 上 ADE 12.49、FDE 28.80，优于 AR CoT 的 13.18/29.98，并且 latency 4.71s 显著低于 10.74s。这里支撑的是视觉世界监督对异常道路拓扑有帮助，而不是单纯 NAVSIM 调参。

Impromptu 则偏开放场景与 nuScenes 轨迹预测式评估。OneVL 的 1.34 ADE、3.70 FDE 比 AR Answer、AR CoT 和 latent CoT baselines 都好。尤其 SIM-CoT 在 Impromptu 上 2.43/6.10 明显落后，说明通用 supervised implicit CoT 在视觉驾驶上的压缩可能丢失关键空间信息。

这两个 benchmark 合在一起支持“latent 被视觉未来监督后更泛化”的主张。但还缺一类实验：如果只换掉 visual tokenizer 或只预测 BEV/occupancy token，是否比未来 RGB token 更好？论文没有做这个替代实验，因此无法判断收益来自“未来视觉监督”本身，还是来自 Emu3.5 IBQ token space 的特殊性质。

10.3 Alpamayo-R1 暴露了强 baseline 仍有优势的角落

Alpamayo-R1 表里 OneVL ADE 2.62 最优，但 FDE 7.53 略输 Cosmos-Reason 的 7.42。这个细节重要，因为 FDE 更关注终点偏差，常反映长时规划意图是否准确。OneVL 在平均路径上更准，但终点并非绝对最好，说明 latent+visual supervision 仍可能在较长时域目标选择上输给更强的语言/世界知识 reasoning baseline。

如果要继续改进 OneVL，一个自然方向是把 visual latent 的预测时域从 0.5s/1.0s 延长到更长 horizon，或者引入多尺度 future token：近未来用于碰撞/车道保持，远未来用于意图和目标区域。当前论文的视觉监督更像短时动态，而不是完整路线级 planning。

11. 复现风险清单：哪些步骤最可能卡住

11.1 权重、训练仓和测试数据的三段式依赖

主仓库 README 标注 model weights、inference code、training code 都公开，但它们分散在 Hugging Face collection、xiaomi-research/OneVL 和 GeorgeLuImmortal/OneVL_training。复现者如果只 clone 主仓库，会得到推理和评估闭环，却拿不到完整训练脚本。这个边界必须明确，否则容易把“能跑 inference”误当成“能复现实验”。

测试数据也有区分：repo 自带 test_data 样例，可用于 smoke test；真实 NAVSIM/ROADWork/Impromptu/AR1 benchmark 需要各自数据集和格式转换。尤其 NAVSIM 不是直接由 eval_results.py 评估，而要先 `output/navsim/convert_to_eval.py` 转成官方 NAVSIM pipeline 输入。这是报告必须写清楚的下游依赖。

视觉解释还有额外依赖：`scripts/visualize_predict_image_tokens.py` 需要 Emu3.5 VisionTokenizer 的 config.yaml 和 model.ckpt。也就是说，即使轨迹推理成功，visual CoT 解码也可能因为 tokenizer 权重缺失而失败。对于调试，应该先跑 trajectory-only，再打开 language decoder，最后打开 visual decoder 和图像解码。

11.2 可重复性需要锁住 prompt 模板和 latent 数

`run_infer.sh` 中 NUM_LATENT=2、NUM_LATENT_VIS=4 看似只是默认参数，实际上必须与训练 checkpoint 对齐。latent 数变化会改变 prefix 长度和 hidden state 位置，辅助 decoder 的输入维度/位置语义都可能不匹配。答案 prefix 也有 benchmark 差异：NAVSIM 常用 `[`，APR1/嵌套列表可能用 `[[`。这些不是格式美观问题，而是输出解析和 metric 计算的前置条件。

因此复现 cheatsheet 应当固定：模型 checkpoint 路径、测试集路径、image_base_path、NUM_LATENT、NUM_LATENT_VIS、ANSWER_PREFIX、PREFIX_K、是否开启 decoder_explain、是否开启 visual_decoder_explain、max token 数。任何 sweep 如果改变这些参数，都应该被视为新实验，而不是同一设置下的误差。

11.3 评估脚本覆盖范围和空白

`eval_results.py` 明确支持 roadwork、impromptu、ar1 三类任务，并在文件头说明 NAVSIM 另走官方 pipeline。报告里把 NAVSIM 与其他 benchmark 混写会误导复现者。正确做法是把 NAVSIM 作为独立评估链：OneVL inference JSON -> convert_to_eval.py -> NAVSIM v1.0 official eval。

此外，开源仓库主要覆盖 inference outputs 的评估，没有提供完整训练日志、随机种子多次运行方差或统计显著性分析。论文结果表看起来完整，但严格复现时仍需要确认 checkpoint 是否唯一、是否有 model selection、是否有不同 seed 的 variance。这里是 OneVL 作为新发布论文的可重复性空白。

12. 可操作的后续研究方向

第一，做 causal probing：对 visual latent hidden states 做局部扰动，观察 decoded future frame、language explanation 和 trajectory 是否一致变化。如果三者不同步，就说明解释 decoder 可能只是可读投影，而不是决策因果链。

第二，比较不同未来监督目标：RGB visual token、BEV occupancy token、agent motion token、map element token。OneVL 证明未来视觉 token 有用，但没有证明它是最优世界模型监督。自动驾驶场景中，BEV/occupancy 可能比前视 RGB 更贴近规划约束。

第三，做 latency accounting：分开统计主 VLM prefill、answer generation、language decoder explanation、visual decoder token generation、VQ decode 成图各自耗时。论文主结果统计 planning latency；解释生成如果在线展示，应另列预算，避免把离线解释成本隐藏起来。

第四，接入 reactive closed-loop：把 OneVL 轨迹放入能反馈其他交通体行为的仿真中，评估它是否因为短时未来视觉监督而更保守或更鲁棒。若闭环中表现下降，说明 non-reactive benchmark 上的视觉世界监督仍不足以覆盖交互因果。

第五，训练一个更小的 ablation：固定 Qwen3-VL backbone，只比较 language-only latent、visual-only latent、dual latent、以及 answer-only，在同一数据、同一输出格式和同一 latency measurement 下跑。论文已有 ablation，但更细的训练曲线和样本效率曲线能回答“哪个监督在低数据下最重要”。

第六，建立解释一致性验证协议。对每个样本同时保存三类输出：轨迹坐标、language aux decoder 的文字解释、visual aux decoder 解码出的未来帧。然后按对象、行为、空间关系三类标签检查一致性：文字是否提到图中可见的风险对象，未来帧是否保留该对象，轨迹是否避让或跟随相应道路结构。这个协议比单独看 LLM Judge 分数更接近安全审计，因为它要求三种解释通道互相约束。若三者冲突，应该把该样本标为 latent explanation failure，而不是只按轨迹 ADE/FDE 计为成功。

第七，把 OneVL 的 latent 监督和数据规模做交互实验。论文证明 full setting 有效，但没有回答视觉辅助监督在低数据、中数据和高数据区间的边际收益是否一致。如果视觉 decoder 主要提供数据效率，它应在低数据区间收益最大；如果它主要提供泛化 inductive bias，则在分布外 benchmark 上收益更明显。这个分析能把 OneVL 从单点 SOTA 推向可预测的 scaling rule。

Critical Block A: Phase 1 Deep Paper Reading

Core Claims

如果只从摘要看，OneVL 很容易被误读成“把 CoT 隐藏起来的又一个 latent CoT 方法”。cleanrun 的证据链显示，它的关键并不是 hidden reasoning 本身，而是把压缩目标从语言摘要迁移到短时未来视觉演化。语言 CoT 可以描述车道、障碍物和意图，但它会丢掉连续空间几何、相对速度和场景演化的因果细节；视觉辅助解码器让 latent 必须保留这些几何动态，否则无法还原 t+0.5s 和 t+1.0s 的视觉 token。

这也解释了为什么 prior latent CoT 在驾驶任务上整体弱于 explicit CoT。COCONUT、CODI、SIM-CoT 的共同假设是语言推理轨迹可以被压缩成连续状态；在数学题或纯语言任务上，这个假设较合理。但驾驶规划的答案是轨迹，监督目标天然是空间和时间。OneVL 把 visual latent 放到 language latent 之前，相当于先用可行动的世界状态约束推理瓶颈，再用 language latent 给语义解释补证。

三阶段训练不是可选工程技巧。Stage 0 先让主 VLM 在带 latent 标记的回答格式中学会轨迹预测；Stage 1 冻结主模型，只训练两个辅助解码器去读稳定的 latent hidden state；Stage 2 再把双辅助 loss 的梯度放回主模型。论文 ablation 中去掉 staged training 会从 88.84 PDM 掉到 67.13，这个幅度说明直接端到端联合训练会让 auxiliary decoder 和主模型互相追逐不稳定目标。

Prefill inference 的细节也需要谨慎理解。OneVL 不是非自回归输出完整轨迹，轨迹 answer token 仍然由语言模型头生成；它消除的是“生成推理 token”的额外串行成本。MLP head 变体进一步把轨迹也转成一次前馈回归，延迟降到 0.24s，但 PDM 从 88.84 降到 86.83。也就是说 paper 的部署路线其实有两档：高精度解释型 OneVL，以及低延迟 MLP head。

OneVL 的核心命题可以拆成三层。第一层是效率命题：显式 CoT 在 VLA 规划里要先生成长推理链，再生成轨迹答案，延迟随推理 token 数增长；如果驾驶系统要接近实时闭环，这种串行开销很难接受。第二层是表征命题：纯语言 latent CoT 把推理压进 hidden state，但压缩目标仍然是语言链，因此学到的更多是语义标签和描述顺序，而不是车辆和道路的连续物理演化。第三层是监督命题：把未来视觉 token 作为训练期辅助目标，可以让同一个 latent bottleneck 同时被轨迹答案、语言解释和未来场景约束，因而比只蒸馏文本 CoT 更接近驾驶任务所需的因果结构。

论文把 compression drives generalization 作为解释框架，但真正可审计的机制是 dual auxiliary decoder。压缩本身既可能帮助泛化，也可能损失信息；只有当压缩目标与下游任务因果变量一致时，瓶颈才会过滤噪声而不是过滤关键信息。驾驶规划的关键变量包括车道拓扑、可行驶区域、相邻 agent 的短时运动、施工区或遮挡导致的可达性变化。这些变量很难用短语言描述完整表达，却可以通过未来帧 token 的预测误差直接约束。

OneVL 与 DriveVLA-W0、LaST-VLA、AdaThinkDrive、Alpamayo-R1 的关系不能只看榜单。DriveVLA-W0 偏向用世界模型生成 dense self-supervision 来扩大 VLA 数据缩放效应；LaST-VLA 与 AdaThinkDrive 更强调 VLA 规划或自适应推理；Alpamayo-R1 更强调长尾动作与 reasoning trace。OneVL 的独特落点是把 world-model objective 内嵌进 latent CoT 训练，让低延迟推理链本身被未来视觉演化监督。

实验 claim 的强度需要分层。四个 benchmark 共同说明收益不是单一数据集偶然；NAVSIM 与 ROADWork 支持 accuracy-latency Pareto，Impromptu 支持开放式驾驶 VLA，APR1 支持更困难 reasoning/planning 场景。但 APR1 上 OneVL 的 FDE 不是最优，因此更准确的结论是：OneVL 在总体 Pareto 和 latent-vs-explicit CoT 比较上成立，而不是所有单项指标无条件第一。

再从因果路径看，OneVL 的收益不应理解为“把解释隐藏起来就更强”。如果只是隐藏解释，模型可能学到更短的语言模板，甚至学到数据集中的答案偏置；真正改变优化问题的是视觉未来监督把 latent 的可接受信息集合收窄到可用于驾驶动作的状态变量。换句话说，latent 的压缩不是目的，压缩后的内容必须能同时解释轨迹、解释文本 rationale、解释未来视觉 token，三者交集才是 OneVL 希望得到的规划表征。

这也给出了一个反事实测试：如果把 visual auxiliary decoder 换成与驾驶无关的辅助任务，例如只预测图像风格、天气类别或随机 mask token，压缩仍然存在，但不一定提高 PDM/ADE/FDE。论文中 visual decoder 的关键不是“多一个 loss”，而是这个 loss 指向短时未来场景演化。只有未来场景与规划动作共享因果变量时，辅助监督才有理由提升轨迹质量。

另一个容易混淆的点是 CoT 可解释性。显式 CoT 的优势是人类可读，但代价是生成长文本；latent CoT 的优势是快，但常常牺牲可读性。OneVL 在两者之间做了折中：训练期保留语言解释读出器，推理期默认不生成解释。这样获得的是“可审计潜变量”，而不是每次部署都完整输出的自然语言推理链。报告中必须保留这个 distinction，否则会把论文 claim 误写成“同时免费获得解释文本”。

从安全审计角度看，OneVL 的解释路径仍然有局限。辅助 decoder 还原的是 latent 中可被 decoder 读出的内容，不等于模型所有决策因果因素的完整列表；如果 decoder capacity 不足，或者训练数据里的 CoT 本身有偏差，language explanation 可能只是局部投影。它比完全黑箱 latent 更可读，但不应该被当成形式化证明。这个限制对自动驾驶尤其重要，因为错误解释会给调试者带来虚假的安全感。

实验表格还需要和任务定义一起读。NAVSIM 的 PDM 是规划质量综合指标，ROADWork 和 Impromptu 更偏 ADE/FDE 轨迹误差，APR1 包含更复杂 reasoning/planning setting。OneVL 在不同任务上的共同特征是速度与性能的 Pareto 改善，而不是每个单项都压倒所有 baseline。正式报告因此把 claim 写成“latent visual supervision 支撑低延迟 planning Pareto”，而不是“所有 benchmark 全面第一”。

训练拓扑的另一个深层含义是 credit assignment。Stage 1 冻结主模型时，decoder 学到的是如何从已有 latent distribution 读出语言和视觉目标；Stage 2 解冻后，decoder 的误差才对主模型 hidden states 形成明确梯度信号。若没有 Stage 1，decoder 的误差既可能表示 decoder 不会读，也可能表示主模型没把信息写进 latent，优化器无法清晰分配责任。w/o staged training 的大幅下降正符合这种 credit assignment 混乱。

Mechanism: Dual Latent Tokens Are A Causal Bottleneck

论文把 latent token 分成 visual 和 language 两类。visual latent 的任务不是输出给用户看的图，而是迫使主模型把轨迹相关的空间动态压缩进少量 hidden states；language latent 的任务是让这些 hidden states 仍能还原为人类可读的 CoT。两者都接在 assistant response 中，但在训练时被不同 decoder 读取。这个设计使 latent 不再只是“短文本摘要”，而是同时接受语义和物理世界演化的双重审计。

具体到 token 数，论文表述为 4 个 visual latent 和 2 个 language latent；实现 README 进一步说明使用原词表 token 表示，visual latent 最终由 35 个原词表 token realization 承载，language latent 由 20 个 token realization 承载。这个细节很重要：如果直接添加 special tokens，repo README 说会导致性能下降；因此代码必须在 tokenizer 输出中寻找由普通 token 拼出的 latent marker。

在方法结构上，visual latent 和 language latent 的顺序也有信息。visual latent 被放在 language latent 之前，说明模型先获得一个面向未来场景的紧凑隐状态，再把语言解释作为后续语义化读出。这个顺序避免了把语言解释当成主干事实源：如果先生成语言 latent，再让视觉 latent 追随，模型可能继续走语言摘要路线；现在视觉 latent 更像是一个可行动世界状态，language latent 则把这个状态投影成可读 rationale。

辅助解码器训练期存在、推理期丢弃这一点会带来一个容易被忽略的优点：解释能力不必在部署路径上支付完整生成成本。训练时，decoder 的存在让 latent hidden state 必须含有可读信息；推理时，如果只需要轨迹，系统可以不调用 decoder。若需要调试或可视化，则可以打开 decoder_explain / visual_decoder_explain。也就是说 OneVL 把解释能力从常规推理成本中解耦出来，形成可按需读出的 latent explanation。

Visual decoder 的作用也不是让模型生成好看的未来图，而是提供一个难以被语言捷径满足的训练信号。若模型只记住语义短语，例如前方车辆、左侧车道线、施工区域，它可能能写出合理解释，却不能预测场景在短时未来如何变化。未来视觉 token 预测要求 latent 保留局部几何和运动趋势，因此能减少纯语义 latent 对驾驶规划的失真。

Language decoder 的作用则是防止 latent 完全变成不可读的控制变量。对于安全系统，只有轨迹性能不够，还需要知道模型把哪些场景因素编码成了决策依据。OneVL 的 language auxiliary decoder 不一定提高最多 PDM，但它让 latent 可以被文本读出，从而支持离线诊断、失败案例归因和人机解释界面。

Math And Algorithm Reconstruction

算法可以重构为五步：第一，把图像、ego state、指令和历史轨迹转成 VLM prompt；第二，在 assistant response 的轨迹答案之前插入 visual latent block 与 language latent block；第三，主 VLM 的 hidden states 在这些位置形成 H_v 与 H_l；第四，训练时分别用 visual auxiliary decoder 和 language auxiliary decoder 解码未来视觉 token 与文本 CoT；第五，推理时丢弃两个 decoder，只保留 latent marker prefill 和轨迹 answer generation。

L = LCE(trajectory, latent positions) + λlLlanguage(Dl(Hl), CoT) + λvLvisual(Dv(Hv, V), future visual tokens)

上式不是论文的逐字公式，而是 cleanrun 的机制重构。它强调三个 loss 指向同一主模型 hidden-state bottleneck：CE 保证轨迹答案可用，language loss 保证语义解释可读，visual loss 保证 latent 包含未来场景动态。若 λ_v 为零，模型仍可学习语言解释，但会退回“符号世界压缩”；若 λ_l 为零，轨迹性能仍强，但人类可解释链条变弱；若 staged training 为零，辅助 decoder 和主模型的目标同时漂移，论文报告 catastrophic collapse。

从信息瓶颈角度看，OneVL 不是简单减少 token 数，而是在少量 latent 位置上施加多任务可解码约束。CE 轨迹损失保证 bottleneck 与最终 answer 对齐；语言解码损失保证 bottleneck 与 human-readable rationale 对齐；视觉解码损失保证 bottleneck 与短时未来场景对齐。三者共同定义了什么信息应该通过瓶颈，什么信息应该被丢弃。

这个机制也解释了为何 token count 不能单独判断容量。论文写 4 个 visual latent 和 2 个 language latent，但实现中用原词表 token 组合承载 marker，因此真正的上下文占用由 token realization 决定。重要的不是标记长度本身，而是主模型在这些位置形成的 hidden state 是否被后续目标有效读取和反向塑形。

若把总损失看成普通多任务学习，会忽略隐藏状态位置选择的关键性。辅助 decoder 不是读取任意 pooled feature，而是读取 latent marker 对应位置的 hidden states。这样做把监督压力集中在少数 prefill 可控位置上，推理时才可以用同样位置承载压缩 reasoning。如果监督分散到全序列，低延迟 prefill 的结构性优势会变弱。

Training Topology

训练拓扑由 preliminary visual decoder pretraining、Stage 0、Stage 1、Stage 2 构成。preliminary 让视觉辅助解码器先在当前帧 ViT embedding 上学习短时未来视觉先验；Stage 0 训练主 VLM 在带 latent token 的格式中做轨迹预测；Stage 1 冻结主模型，只让 auxiliary decoders 对齐稳定 latent distribution；Stage 2 解冻所有组件，把 CE、language 和 visual objectives 联合优化。

这个 curriculum 与普通多任务训练的差别在于优化顺序。普通端到端会让 visual decoder 在 latent 尚无意义时尝试预测未来帧，等价于给一个未成形 bottleneck 加上过强外部目标；OneVL 先固定 decoder prior，再固定主模型 latent distribution，最后才联合收紧。这解释了 ablation 中 gradient shock 和 task interference 的说法。

Stage 0 的必要性在于先建立 latent position 与轨迹答案之间的信息路由。没有这个 warmup，辅助 decoder 在 Stage 1 读到的 hidden states 可能只是格式占位，而不是规划相关表征。换句话说，Stage 0 不是为了直接获得最终性能，而是让 latent 位置变成主模型愿意使用的信息节点。

Stage 1 的冻结策略解决了 moving target 问题。若主模型和 decoder 同时变化，decoder 学到的映射会追逐一个不断漂移的 hidden-state distribution；冻结主模型让 decoder 先学会解释稳定 latent。这个阶段更像读出器校准，而不是最终 joint optimization。

Stage 2 才是真正把世界模型监督回传到主 VLM 的阶段。此时 decoder 已经会读 latent，主模型也已经会用 latent 做轨迹预测，双辅助 loss 的梯度才更可能改善表征，而不是造成初始化冲击。论文报告 w/o staged training 的 gradient norm 爆炸和 trajectory loss 恶化，正说明直接 joint training 破坏了这种顺序。

训练成本是 OneVL 的主要工程风险。论文提到训练期大约需要三份 4B 模型实例，虽然 DeepSpeed ZeRO-2 可以缓解，但仍然是非平凡基础设施要求。因此 OneVL 的“低延迟”主要指推理路径；阅读代码或迁移方法时必须把训练显存、checkpoint 保存策略、数据规模和 aux decoder 初始化列入设计边界。

Critical Block C: Phase 3 Code Implementation

代码证据显示，OneVL 的实现不是单个模型类，而是两个仓库合起来形成闭环：inference repo 负责 standalone checkpoint inference、latent marker parsing、辅助 decoder explanation、visual tokenizer decode 和 benchmark conversion；training repo 负责基于 ms-swift 的 SFT/latent-CoT training scripts、loss 接入和模型集成。

代码实现的第一层是 latent marker 的工程处理。论文写的是 visual latent tokens 和 language latent tokens，但 repo README 说明不新增 special tokens，而是用原词表 token 表示。这会让实现复杂很多：代码不能简单查一个 special token id，而要在 tokenizer ids 中寻找 start/end、latent、vis suffix、pipe 等组件构成的模式。compute_inference_latent_positions 和相关 helper 正是在解决这个定位问题。

第二层是辅助 decoder 权重加载。build_aux_decoder_from_checkpoint 和 build_projection_from_checkpoint 通过 checkpoint prefix 取出 language/visual auxiliary decoder 与 projection 权重。这个设计意味着 OneVL checkpoint 必须是一个组合 checkpoint：不仅有主 Qwen3-VL 权重，还要包含辅助 decoder、projection、可选 float head 等附加模块。若只有 backbone 或 LoRA adapter，不一定能打开解释路径。

第三层是解释解码路径。decode_latent_with_aux 将 language latent hidden states 投影为辅助语言模型的输入 embedding，然后逐 token 生成解释文本；decode_latent_with_visual_aux 对 visual latent 做类似处理，生成视觉 token 字符串。这里的可解释性不是来自主模型直接输出的普通自然语言，而是从 latent hidden state 反解出来，这一点正对应训练期辅助 decoder 认证 latent 内容的思想。

第四层是常规轨迹输出路径。默认推理不需要解释 decoder，只需要构造含 visual/text latent marker 的 assistant prefix，然后让主模型生成 answer token。输出再由评估脚本解析成 waypoint 或 benchmark JSON。这个路径解释了为什么 OneVL 能接近 answer-only latency：辅助 decoder 不在热路径上，latent marker 在 prefill 中并行处理，串行部分主要剩下轨迹 token。

第五层是 MLP head。代码中的 FloatMLPHead 只支持 mlp head_type，并通过 last latent hidden state 做 float waypoint regression。论文里 MLP variant 达到 0.24s，但 PDM 下降到 86.83；代码层面说明这不是简单打开一个 decoder，而是换了轨迹输出头。阅读指标或实现差异时必须明确是 AR trajectory head 还是 MLP head，否则 latency 和 accuracy 数字没有可比性。

第六层是 evaluation scripts。eval_results.py 覆盖 ROADWork、Impromptu、AR1 的 ADE/FDE/latency，NAVSIM 还需要 convert_to_eval 和外部 PDM evaluator。cleanrun 的最小 smoke 能证明这些 Python 文件语法正确、CLI 入口存在，但不能证明 benchmark metric 已重跑。为了避免运行等于正确的错误，code_smoke_test 明确记录 full_inference_blocked。

training repo 的阅读要警惕噪声。它是 ms-swift 体系，包含大量与 OneVL 无关的通用训练文档、GRPO、LoRA、Megatron、测试和示例。OneVL 相关证据主要在 README 的 OneVL training pipeline、demo_data/navsim、run_script/train/navsim/stage scripts，以及 latent_cot 相关 loss/model 模块。code_evidence_index 选择 18 个 entries，就是为了把这些相关入口从通用框架中分离出来。

从代码阅读角度，当前 cleanrun 最可靠的信息不是 benchmark 数字，而是实现断点：latent marker 如何定位、checkpoint prefix 如何加载、aux decoder 如何读 hidden states、trajectory parser 如何消费输出。任何关于指标的讨论都不能用 README 数字替代这些下层实现证据。

代码映射里最重要的不是文件数量，而是 claim 到实现对象的可追踪性。latent token design 对应 tokenizer pattern 和 latent position helper；visual auxiliary decoder 对应 checkpoint prefix、projection、visual tokenizer decode；language auxiliary decoder 对应 hidden-state projection 和 autoregressive explanation generation；prefill inference 对应 assistant prefix 和 decoder bypass；MLP head 对应 FloatMLPHead 与 waypoint regression。每个 claim 都必须有文件级或函数级锚点，否则只是论文复述。

infer_onevl.py 的依赖失败也有信息。`--help` 在 import torch 之前就被拦住，说明脚本没有把重依赖延迟到命令解析之后。这不是算法错误，但会影响轻量可用性：想做 CLI discovery 或参数 introspection，也需要先装 torch。code_smoke_test 因此把它标为 missing dependency blocker，而不是把 exit 1 当成正常 help 成功。这种区分符合“运行不等于正确”的规则。

training repo 的 stage scripts 应被看成实现逻辑索引，而不是已验证配置。脚本中暴露的 latent counts、loss weights、freeze/unfreeze 策略和模型类型能支持论文机制解释；但实际训练还需要数据集切分、GPU 数量、ZeRO 配置、checkpoint save policy、随机种子和完整依赖版本。当前报告只记录这些边界，不把它扩展成训练计划。

Implementation Logic Narrative

`infer_onevl.py` 首先通过 tokenizer pattern helper 找到 visual/text latent block 的位置；如果请求解释，它会额外跑一次需要 hidden states 的 forward，将 latent hidden states 投影到辅助 decoder input embedding 空间，再自回归解码文字解释或视觉 token 序列。常规轨迹预测则通过 processor.batch_decode 得到输出文本，后续评估脚本再解析 waypoint。

视觉解释路径依赖 Emu3.5/IBQ visual tokenizer。repo 中的 `visual_tokenizer/tokenization_qwen3vl_visual.py` 和 `scripts/visualize_predict_image_tokens.py` 说明视觉 token 不是普通图像像素，而是离散 visual-token vocabulary；这与论文的“predict future-frame tokens”一致。

训练仓库的 README 与 stage scripts 把论文阶段变成可执行命令。Stage 1 脚本显式暴露 latent counts、loss weights、visual conditioning 和冻结主模型的意图；Stage 2 脚本切换到 `qwen3_vl_latent_cot` 并联合优化。由于仓库是 ms-swift fork，大量文件是通用训练基础设施；本报告的 code_evidence_index 只抽取 OneVL 相关入口。

代码细节上还要注意三个容易被忽略的接口层。第一，latent marker 并不是一个新增 special token，而是由原词表 token 组合出的模式，因此定位逻辑天然比论文符号更复杂。第二，辅助 decoder 不是从任意 pooled feature 读出，而是从特定 latent position 的 hidden states 读出；这让训练监督能集中塑形少数 prefill 位置。第三，visual tokenizer 与 ordinary image decoder 不同，它处理的是离散 visual-token vocabulary；所以视觉解释路径的输出首先是 token stream，再由工具还原为可视内容。这些接口层决定了读代码时应沿 tokenizer -> latent position -> projection -> aux decoder -> output parser 的顺序，而不是只搜索一个总模型类。

训练仓库的噪声也需要在报告中显式剥离。OneVL_training 继承了大量 ms-swift 通用能力，包括通用 SFT、LoRA、分布式训练、评测和示例脚本；这些文件能解释工程环境，却不能直接证明 OneVL 方法贡献。真正与论文 claim 对齐的代码锚点是 latent_cot loss/model、NAVSIM stage scripts、demo_data/navsim、以及 README 中对 Stage 0/1/2 的参数说明。把通用框架层和 OneVL-specific 层分开，是本次代码分析比复现 checklist 更有价值的地方。

Cross-Paper Positioning And Limitations

相对 DriveVLA-W0、LaST-VLA、AdaThinkDrive、Alpamayo-R1 等 VLA/planning 工作，OneVL 的独特位置是“解释压缩 + 世界模型监督 + answer-only latency”。它不是最大模型路线，也不是纯 world model data scaling 路线，而是把 world-model-like future prediction 降格为训练期辅助约束，用较小成本改善 trajectory latent。

限制同样明确。第一，训练期需要约三份 4B 模型组件的显存，论文也承认约 3x memory pressure；第二，latent token count 是经验设定，缺少系统 scaling；第三，当前视觉 world model 只覆盖短时未来帧 token，未覆盖 360-degree multi-camera；第四，本地 cleanrun 没有完整权重和 benchmark 数据，因此不能独立证明作者数值，只能验证证据一致性和实现路径。

最重要的反驳点是：OneVL 的性能提升是否来自“compression drives generalization”这个高层原则，还是来自更具体的视觉未来预测辅助任务和 curriculum？论文证据更强地支持后者。compression 是解释框架，visual auxiliary + staged training 是可验证机制。若未来另起项目复现，才需要系统 ablate visual horizon、latent count、decoder capacity 和 Stage 1 freeze policy；本报告当前只把这些作为论文理解和代码阅读线索。

总体来看，OneVL 最强的证据链是：视觉未来监督显著改善 latent planner 的任务相关性，三阶段训练保证辅助目标不会破坏主模型，prefill inference 把解释生成成本移出热路径，MLP variant 展示部署速度上限。最弱的证据链是：是否所有提升都来自 compression 本身，是否能在更多摄像头、更长 horizon、更复杂交互和不同 base VLM 上稳定复现。这些弱点不是报告漏洞，而是论文后续应验证的研究问题。

本 cleanrun 的正式结论因此保持两级：学习层面，OneVL 是一个值得重点关注的 driving VLA latent reasoning 方法，因为它把世界模型监督和可读解释压入同一 latent bottleneck；代码层面，当前本机只完成资料、代码和轻量 smoke 的 evidence-backed analysis，完整推理被 torch/权重/数据阻塞，benchmark 数字仍是作者报告而非本地重跑。这个边界必须写清楚，才能让对比表和完成门都可信。

如果用工程负责人视角评估 OneVL，最应该先问的不是“PDM 是否比某个 baseline 高 0.5”，而是“这个方法把哪些风险从线上推理转移到了离线训练”。它把显式 CoT 的长文本延迟转移为训练期辅助 decoder 和视觉 token 预测，把解释读出的成本转移为按需 decoder path，把轨迹质量和解释质量的耦合转移为多阶段 curriculum。这个迁移是否划算，取决于目标系统更在意线上 latency 还是训练基础设施成本。

如果用代码审计视角评估 OneVL，最应该优先补的不是更多摘要，而是四个可验证断点：第一，latent marker 在 tokenizer ids 中的定位是否与论文设定一致；第二，aux decoder checkpoint prefix 是否完整存在；第三，demo inference 输出的 latent explanation 是否与轨迹文本同步；第四，转换后的 benchmark JSON 是否被官方 evaluator 正确读取。只有这些断点逐一通过，README 和论文表格中的 PDM/ADE/FDE 数字才有资格被进一步讨论。

因此，本次 cleanrun 与旧 run 的差别不在于结论相反，而在于证据边界更显式：旧 run 规模更大、正文更长、图表更多；cleanrun 则强调从零下载、从零 clone、从零生成，并把项目页/HF 失败、torch 缺失、权重未验证等阻塞条件写进 evidence gate。正式对比表应读成 workflow 形态对比，而不是方法学结论对比。两次都支持 OneVL 的核心机制判断，但都没有在本机完成 full benchmark reproduction。

还有一个需要在正式报告中强调的误用风险：如果只看 0.24s 的 MLP head 数字，可能会把 OneVL 误当成一个纯高速 waypoint regressor；如果只看语言解释 decoder，又可能把它误当成一个可免费输出完整 CoT 的解释系统。论文真正有价值的组合是训练期三目标约束、推理期 prefill latent、可选解释读出和可选 MLP head 四者的 Pareto 设计。不同部署目标应选择不同路径，而不是把所有数字混在同一个配置下比较。

若以后单独启动复现实验，也不应直接从最大 benchmark 开始。更稳健的路线是先重建最小闭环，再扩大数据和指标。当前报告不执行这条路线，只把它作为代码边界说明，避免把论文学习任务扩大成工程复现任务。

从论文学习角度，OneVL 的启发是：自动驾驶 VLA 的 reasoning 不一定要以人类语言链的形式完整显式化，关键是中间状态是否被任务相关监督塑形并可在需要时读出。这个思想可以迁移到其他闭环任务，例如移动机器人导航或操作规划，但迁移时必须重新选择辅助监督目标；如果目标任务的关键状态不是未来视觉 token，而是接触状态、地图拓扑或多智能体意图，那么 visual decoder 的形式也应相应改变。

最后，本报告把 code-backed analysis 和 metric reproduction 严格分开。前者已经通过新 clone 仓库、文件级证据索引和最小 smoke 支撑；后者仍需要 torch、CUDA、模型权重、视觉 tokenizer、benchmark 数据和官方 evaluator。这个分离会让结论显得更保守，但它能避免把作者发布的数字包装成本地复现结果。

因此，后续任何汇报若写到“复现成功”，都必须附带本地生成的预测文件、评估命令、evaluator 输出和指标日志；在这些 artifact 出现之前，只能称为代码证据分析完成，不能称为指标复现完成。

摘要

链式思维（Chain-of-Thought, CoT）推理已经成为基于 VLA 的自动驾驶轨迹预测中的重要驱动力。然而，标准 CoT 的自回归生成方式会带来明显的时延成本，这种成本对于实时部署而言通常不可接受。潜在 CoT 方法试图通过把推理压缩到连续隐藏状态中来缩小这一差距，但它们在性能上始终落后于显式 CoT。本文认为，问题的根源在于纯语言潜在表示压缩的是世界的符号化抽象，而不是实际支配驾驶行为的因果动态。

为此，本文提出 OneVL，即 One-step latent reasoning and planning with Vision-Language explanations。OneVL 是一个统一的 VLA 与世界模型框架，它把推理路由到紧凑的潜在 token，并用两个辅助解码器对这些潜在表示进行监督。除重构文本 CoT 的语言解码器外，本文引入一个视觉世界模型解码器，用于预测未来帧 token，从而迫使潜在空间内化道路几何、交通参与者运动和环境变化的因果动态。

OneVL 采用三阶段训练流程，逐步把潜在表示与轨迹、语言和视觉目标对齐，以保证联合优化稳定。推理时，两个辅助解码器均被丢弃，所有潜在 token 在一次并行预填充中写入上下文，使时延与仅输出答案的预测基本一致。在四个基准上，OneVL 成为第一个超过显式 CoT 的潜在 CoT 方法，并以 answer-only 的时延获得更高准确率。这些结果表明，在世界模型监督下，潜在 CoT 可以形成比逐 token 冗长推理更具泛化性的表示。

1 引言

视觉-语言模型（Vision-Language Models, VLMs）已经快速成为自动驾驶中的基础构件。它们在一个模型内统一了整体场景理解、自然语言推理与端到端轨迹规划。当这些模型进一步扩展到输出轨迹航点或控制信号等动作结果时，通常被称为视觉-语言-动作模型（Vision-Language-Action models, VLAs）。

近来 VLA 驾驶模型进展的一个核心推动因素是链式思维推理。模型在提交最终轨迹之前显式写出中间推理步骤，可以显著提升预测质量。通过显式呈现场景语义、预期的交通参与者行为和高层驾驶意图，CoT 监督把预测结果绑定为连贯的因果链，并明显降低规划错误。这一现象与更广泛的大语言模型 CoT 研究一致，包括数学推理、文档理解、代码合成、多模态问答、基于强化学习的深度推理和测试时扩展等方向。

关于 CoT 为什么有效，一个统一解释来自“智能的压缩视角”：在下一 token 监督下，被迫表达中间步骤的模型必须把自身理解压缩成结构化、可泛化的表示，而不是记忆浅层输入-输出映射。

然而，把 CoT 部署到真实驾驶系统中，会暴露解释性与效率之间的尖锐矛盾。标准自回归 CoT 必须先生成所有推理 token，随后才能生成轨迹，因此推理时延与推理链长度成正比，远高于仅输出答案的预测。在安全关键的实时场景中，这一差距通常不可接受。另一方面，显式 CoT 链高度冗余：许多 token 只是重复上下文或遵循模板化表达。这说明，关键推理内容应当可以压缩为更紧凑的形式，同时不牺牲、甚至强化泛化能力，因为更紧的压缩会迫使模型只保留真正影响预测的因果结构。

Latent CoT 及其局限

已有一系列工作正沿着这一方向推进，用紧凑潜在表示替代显式推理 token。COCONUT 通过课程学习逐步把离散推理步骤替换为连续向量；CODI 进一步采用自蒸馏，使学生模型在潜在空间中模仿教师模型的 CoT 行为；SIM-CoT 增加独立文本解码辅助解码器，在潜在训练阶段提供直接文本监督。

但是，把这些方法适配到基于 VLA 的驾驶任务时，会出现关键缺陷。COCONUT、CODI 和 SIM-CoT 主要为纯语言推理设计，没有利用定义驾驶场景的丰富视觉结构。因此，它们的纯语言潜在表示不足以承担轨迹预测所需的多模态推理。图 1 显示，已有所有潜在 CoT 方法在各基准上均低于显式 CoT。

更根本地，驾驶场景的自然语言描述本身就是抽象的。语言编码的是语义标签，而不是决定未来结果的时空因果动态。压缩语言的潜在向量压缩的是世界的符号化抽象，而不是世界的底层因果结构。另一个限制是，先前方法中的潜在隐藏状态通常仍以自回归方式产生，即一次生成一个潜在隐藏状态，推理依然是序列化的。本文的目标则是在一次预填充中生成所有潜在隐藏状态。图 2 对比了显式 CoT、既有隐式潜在 CoT 和 OneVL 三种范式，并给出本文设计动机。

OneVL：一步式潜在推理与带视觉-语言解释的规划

本文提出 OneVL，用两个关键创新克服既有潜在 CoT 方法的局限。第一，本文引入双模态辅助解码器：语言辅助解码器从紧凑语言潜在 token 中重构可读 CoT 推理；视觉辅助解码器从视觉潜在表示中预测未来帧。视觉解码器承担世界模型辅助的角色。通过迫使压缩潜在表示预测未来时刻的场景外观，模型的瓶颈表示会编码真正的因果场景动态，例如交通参与者轨迹、道路几何演化和新出现的危险，而不是抽象符号摘要。

这正是纯语言潜在 CoT 缺失的要素。未来帧预测是一个具体的压缩目标，直接反映物理世界的因果结构；这一目标比单纯文本描述更符合智能压缩视角。由此得到的框架在同一模型中同时处理规划、语言推理和视觉解释。

除解释性外，双重重构目标还有更深层作用：它们保证压缩潜在表示编码的是可泛化结构，而不是表面相关性。如果紧凑潜在 token 能同时被解码为连贯语言推理与合理未来帧，模型就必须发现可迁移的场景动态表示，而不是记忆输入-输出映射。视觉预测以物理场景动态约束 latent，语言监督以语义意图约束 latent，二者共同保证压缩表示满足稳健轨迹规划的语义与因果要求。

第二，本文设计预填充推理机制。推理时，视觉与语言潜在 token 被作为固定 prompt 输入预填到模型上下文中，使所有 latent token 能在单次并行预填充中处理。这消除了迭代生成潜在 token 的开销，使推理速度基本等同于仅答案自回归预测。最终模型在统一序列中完成一步式潜在推理、视觉-语言解释和规划。实验上，OneVL 不仅匹配而且超过显式自回归 CoT 的轨迹质量，说明压缩并非必要妥协，而是更有效推理的驱动力。

贡献

  • OneVL 框架。 本文提出一种基于“压缩驱动泛化”原则的潜在 CoT 框架，并指出既有潜在 CoT 在规划任务中的关键缺口：纯语言潜在表示过于抽象，无法满足规划任务对因果场景动态的需求。本文用语言解码器与视觉世界模型解码器共同监督紧凑 latent，使其同时编码语言推理与未来场景动态。
  • 四个基准上的优越性能。 OneVL 在多个基准上取得领先表现，是唯一超过显式自回归 CoT 的潜在 CoT 方法。消融研究确认各组件均有贡献，视觉解码器、语言解码器和分阶段训练流程都很重要。
  • 预填充推理。 推理阶段丢弃辅助解码器，并把所有潜在 token 预填到 prompt 中，实现无迭代开销的一步式潜在 CoT 推理。NAVSIM 上，其时延接近 AR answer-only，并比显式自回归 CoT 快 1.5 倍；ROADWork 上，预填充时延与 answer-only 相同，并比显式 CoT 快 2.3 倍。若追加 MLP 轨迹头，时延可降至 0.24 秒，即 4.16 Hz。
  • 可解释解释。 语言辅助解码器可从压缩 latent 中恢复高质量 CoT 文本，视觉辅助解码器可生成空间上一致的未来帧预览，从语言与视觉两侧提供解释性。

2 相关工作

2.1 隐式与潜在链式思维

由于显式 CoT 的推理开销与推理链长度成正比，越来越多研究尝试把推理内化为连续潜在表示。Deng 等提出逐步内化课程，把每个显式推理 token 逐步替换为隐式内部计算，使模型一步一步吸收 CoT。COCONUT 将这一思想推广到连续 latent thought tokens，通过分阶段课程在 LLM 隐藏状态空间中进行类似广度优先的路径探索。Compressed Chain of Thought 采用互补的蒸馏思路，把显式 CoT 轨迹压缩为少量稠密摘要向量并拼接到输入前，在显著缩短长度的同时只带来有限精度损失。

CODI 采用序列级自蒸馏，使学生模型把锚点潜在隐藏状态，通常是答案前的最终隐藏表示，对齐到教师模型完整 CoT 序列，从而在保留效率的同时缩小性能差距。Token Assorted 提供一种折中方式，在同一序列中交错离散文本 token 与连续 latent token，使显式与隐式推理之间可以连续插值。SIM-CoT 指出了 latent token 数量增加时表示可能坍缩的潜在不稳定问题，并通过可插拔辅助解码器在训练阶段把每个隐式 token 与相应显式推理步骤对齐。

如前文所述，这些方法均为纯语言任务开发，不能有效迁移到基于 VLA 的自动驾驶。

2.2 面向自动驾驶的 VLM 与 VLA

除基础 VLM 工作与 CoT 增强驾驶模型外，还有一条研究线关注为语言驱动驾驶建立更丰富的评测与监督信号。MapLM 提出了针对地图与交通场景理解的大规模基准，用于检验 VLM 是否能从传感器数据中解析结构化道路拓扑。Ding 等将鸟瞰特征注入 VLM，使单一多模态模型能融合相机视角与俯视空间上下文。相关工作还研究了 corner-case 评估与风险定位，以压力测试 VLM 在稀有或安全关键场景下的推理能力。

更接近轨迹预测的方向中，近期 VLA 模型把语言推理与航点或动作输出结合起来。DriveVLA-W0 使用世界建模生成稠密自监督信号，从而放大 VLA 驾驶中的数据扩展规律。AdaThinkDrive 引入面向驾驶决策的自适应 CoT，LaST-VLA 在驾驶数据上训练大规模 VLA，Alpamayo-R1 则显式连接推理轨迹与长尾动作预测。OneVL 建立在这些基础上，但用双模态潜在监督和预填充推理处理显式 CoT 的时延成本，在不牺牲解释性的情况下获得竞争性能。

2.3 自动驾驶世界模型

世界模型概念源于基于模型的强化学习，其目标是模拟人类认知过程，并预测动作对环境演化的影响，尤其是在三维和四维空间中。为了增强空间推理能力，一些方法引入先进感知框架，以实现更稳健的三维环境理解。随着视频生成发展以及 Joint Embedding Predictive Architecture 的提出，世界模型的范围和应用显著扩大。在自动驾驶中，世界模型通常服务于三个目标：数据生成、闭环评估和表示学习。

在数据生成方面，Cosmos 结合文本、图像、视频和运动信号等多模态输入，为机器人和自动驾驶训练合成一致数据。在闭环评估方面，DICC 利用生成式世界模型产生逼真驾驶图像，并对端到端驾驶系统进行对抗评估以提升安全性与鲁棒性。类似地，AD-R1 利用世界模型的高物理保真度，将其作为交互式模拟器进行强化学习，从而降低挑战场景中的安全违规。表示学习方面，DriveVLA-W0 引入来自世界模型的未来时序信息以提升轨迹规划，DynVLA 通过建模帧间相似性降低生成图像冗余，在保持性能的同时降低推理时延。

与上述方法不同，OneVL 在单一 VLA 内部把短时未来视觉 token 预测作为训练期世界模型辅助，并与压缩潜在 CoT 结合。这一辅助信号在语言-only 隐式 CoT 不足的地方，把瓶颈表示推向因果场景动态。推理时该辅助模块被丢弃，使预填充 latent 达到 answer-only 时延。既有工作多强调数据生成、模拟器或独立表示栈，而不是以语言和视觉双重约束共同认证 latent bottleneck。

3 模型架构

OneVL 在预训练 VLM 上增加紧凑潜在 token 接口与两个用于多模态解释的辅助解码器。图 3 给出整体结构。

3.1 主视觉-语言模型

OneVL 的主干是 Qwen3-VL-4B-Instruct。该 VLM 处理交错的图像和文本输入，由三个标准组件构成：视觉编码器（ViT）、视觉投影器（MLP 对齐器）和大语言模型（LLM）。三者均从 Qwen3-VL-4B-Instruct checkpoint 初始化，并在 Stage 0 和 Stage 2 中保持可训练。主干主要通过标准下一 token 预测目标进行优化，即对轨迹答案和下文引入的潜在推理 token 施加交叉熵损失 L_c。

3.2 潜在 token 设计

OneVL 的一个关键设计是引入专门的潜在 token，作为隐式推理的紧凑载体。本文定义两类潜在 token。

语言潜在 token。 固定长度 C_t = 2 的语言潜在 token 序列，由起止分隔符包围。这些 token 放在助手响应中、轨迹答案之前，占据标准自回归模型中显式 CoT 推理原本所在的位置。LLM 处理后在这些 token 位置抽取的隐藏状态编码模型的隐式语言推理。

视觉潜在 token。 固定长度 C_v = 4 的视觉潜在 token 序列，同样由起止分隔符包围，并放在语言潜在 token 之前。这些 token 用于编码关于未来场景状态的空间和时间视觉推理。

两组潜在 token 都是推理载体，它们在 VLM 输出层对应的隐藏状态会被送入辅助解码器。实现中，作者发现向 VLM 词表加入专用特殊 token 会导致性能下降。因此，实际使用原始词表表示潜在 token：C_v 个视觉潜在 token 实现为 35 个普通 token，C_t 个语言潜在 token 实现为 20 个普通 token。

3.3 语言辅助解码器

语言辅助解码器 D_l 的目标是从紧凑语言潜在隐藏状态中恢复人类可读的 CoT 推理文本。对每个训练样本，主模型中的语言潜在 token 产生隐藏状态 H_l，维度为 C_t × d，其中 d 是 LLM 隐藏维度。此外，模型还提供来自主干当前帧 ViT patch embedding 的视觉 token V，长度为 N_v。一个 MLP 层把两个分支映射到辅助解码器的 embedding 空间，随后通过拼接形成多模态输入：

Z_l = [ W_l(V), W_l(H_l) ]

其中 W_l 是使 Z_l 匹配 LLM 输入维度的 MLP。Z_l 被输入语言辅助解码器 D_l。

语言辅助解码器在 Z_l 条件下预测真实 CoT 推理文本 T_y_t，其训练目标是 teacher-forcing 交叉熵：

L_l = - sum_i log P_D_l(T_y_t,i | Z_l, T_y_t,<i)

该损失鼓励主模型的语言潜在 token 编码与驾驶场景相关、且能够解码为自然语言推理的语义信息。

3.4 视觉辅助解码器

视觉辅助解码器 D_v 旨在预测未来帧视觉 token。自动驾驶本质上是一个时空预测任务；未来帧视觉 token 表示近未来驾驶场景外观，是学习视觉潜在表示的自然目标。该目标作为世界模型辅助，补充纯语言潜在 CoT。预测未见配置要求模型形成稳健因果模型，而不是记忆模式，因此它也是对泛化能力的严格检验。视觉与语言解码器结合后，框架同时用物理动态和语义意图监督 latent，施加多模态约束以捕捉环境共享因果结构。

设 V 表示当前帧 ViT embedding，H_v 表示主模型视觉潜在 token 的隐藏状态，W_v 是 MLP 层。视觉辅助解码器接收二者拼接：

Z_v = [ W_v(V), W_v(H_v) ]

这种同时依赖当前视觉上下文与 latent 状态的条件输入，使解码器能够执行条件未来帧预测。

为了把图像表示为离散 token 序列，本文采用 IBQ 视觉 tokenizer，并使用 Emu3.5 tokenizer 的 131,072 个离散视觉码本。图像被缩放到最大 512 × 512 像素。为了把该视觉词表接入 OneVL，Qwen3-VL-4B 基础词表扩展了 131,072 个视觉 token ID。训练时的视觉 token 序列通过对数据集真实未来帧离线运行 IBQ tokenizer 构建，不需要额外训练前向传播。

设 T_y_v 是 +0.5s 与 +1.0s 两个未来帧的离散视觉 token 拼接序列，视觉损失为：

L_v = - sum_t log P_D_v(T_y_v,t | Z_v, T_y_v,<t)

3.5 联合训练目标

总训练损失 L 是三个分量的加权和：

L = L_c + lambda_l L_l + lambda_v L_v

其中 L_c 是主模型交叉熵损失，lambda_l = 1.0 是语言解释损失权重，lambda_v = 0.1 是视觉解释损失权重。L_v 权重较低，是因为视觉 token 重构更难，较小权重可防止其主导训练信号。

3.6 预填充推理

推理时，辅助解码器被丢弃。关键效率洞见是，视觉与语言潜在 token 可作为固定 token 序列预填到 prompt 上下文中，因为这些 token 的词表身份已经在训练中被模型见过。推理 prompt 由系统信息、用户查询、视觉 latent 起止符与 latent-vis 序列、语言 latent 起止符与 latent 序列共同构成。

所有潜在 token 被放入预填充阶段，而不是解码阶段。现代 Transformer 能并行处理整个 prefill，因此相比已经很长的图像 patch 序列，这些额外 latent token 带来的开销可忽略。模型随后只自回归生成轨迹 token。因此，OneVL 获得近似 answer-only 自回归预测的时延，同时主模型对预填充潜在 token 的处理仍会激活训练中学到的推理路径。

最终，模型输出包括：轨迹预测，即自动驾驶未来航点；语言解释，即通过辅助解码器获得的人类可读 CoT；视觉解释，即通过视觉辅助解码器获得的未来帧视觉 token。后两者可用于事后解释生成、人机协同调试、安全审计或人机交互，而轨迹预测始终是推理时的主输出。

4 三阶段训练流程

训练 OneVL 存在独特优化挑战：主 VLM、语言辅助解码器和视觉辅助解码器必须联合优化，但三者学习目标不同，初始对齐状态也不同。本文通过一个初步自监督预训练步骤和三个主阶段解决该问题。训练配置见表 8。

4.1 初步阶段：视觉辅助解码器自监督预训练

在把视觉辅助解码器接入完整 OneVL 流程之前，作者首先把它作为未来帧生成器独立预训练。动机很直接：若训练早期 latent token 尚未携带信息，就立刻要求解码器在其条件下预测未来帧，会形成病态任务并阻碍学习。相反，作者先让解码器依赖当前帧 ViT embedding 学习强无条件先验，即根据当前帧预测接下来两个时间戳的场景外观，然后再引入 latent 条件信号。该阶段在概念上类似自监督视频预测：解码器仅从视觉观测中学习，不使用推理监督。

此阶段视觉辅助解码器 D_v 只接收当前帧 ViT embedding V，经 Proj_v 投影后作为输入；视觉潜在 token 隐藏状态 H_v 不参与，因为主模型尚未连接。使用第 3 节定义的未来帧视觉 token 序列 T_y_v，预训练损失为：

L_p = - sum_t log P_D_v(T_y_v,t | V, T_y_v,<t)

预训练完成后，解码器已经学习到稳健的视觉动态先验，可以仅根据当前场景预测合理未来帧。此组件因此构成模型的隐式世界模型，捕捉视觉演化规律。当它随后接入主模型时，视觉潜在 token H_v 会作为额外条件信号与 ViT embedding 一同输入。由于这些 latent token 编码了主模型推理得到的规划动作，解码器实际上从无条件下一帧生成转变为动作条件世界模型 rollout。由此，视觉 latent token 可被解释为一种紧凑、可行动的表示，用于引导世界模型预测。

4.2 Stage 0：主模型预热

辅助解码器能提供有意义监督的前提，是主模型的潜在 token 已经携带与推理内容语义对齐的信息。如果没有针对性预热，这些 token 不会产生能被辅助解码器解码的有效隐藏状态。

Stage 0 通过在轨迹预测任务上端到端训练主 VLM 来解决这一问题，每个训练样本的 assistant response 中都嵌入 latent token。模型学习两件事：第一，预测准确轨迹，主交叉熵损失覆盖 latent token 与轨迹答案 token，使模型形成基础预测能力；第二，形成有意义 latent 表示，latent token 在 prompt-response 结构中与轨迹目标共同出现，模型自然会利用这些位置编码对轨迹预测有用的中间表示。同时，注意力机制允许轨迹 token 关注 latent 位置，建立后续辅助解码器可利用的信息路由路径。

4.3 Stage 1：辅助解码器预热

当主模型已能产生稳定、有意义的 latent 表示后，Stage 1 专门训练辅助解码器与这些表示对齐。关键在于冻结主模型，使辅助解码器面对一致的语义分布。保持稳定性后，解码器能更有效地学习固定 latent 特征到视觉和语言推理的映射。

Stage 1 中，语言辅助解码器 D_l 学习解码语言 CoT 推理文本，并用 L_l 对真实推理标注进行微调；视觉辅助解码器 D_v 用 L_v 学习预测两个未来帧。

4.4 Stage 2：联合端到端微调

Stage 2 使用联合损失 L 对全部三个模型组件进行共同微调。L_l 与 L_v 的梯度此时会回传到主模型，直接塑造 latent 表示，使其同时服务于轨迹预测、语言解释和视觉预测目标。这形成一个正循环：更丰富的 latent 表示帮助主模型做出更好轨迹预测，辅助解码器也会适应更新后的 latent 表示，从而提升解释质量。Stage 2 之所以可行，正是因为主模型和辅助解码器都已经充分初始化。消融实验表明，跳过三阶段训练会显著降低性能。

5 实验

本节在四个基准上对 OneVL 进行全面定量评估，并通过消融研究与分析分离各性能增益来源。

5.1 数据集

本文在四个互补基准上评估 OneVL：NAVSIM、ROADWork、Impromptu 和 Alpamayo-R1。选择这些数据集，是因为它们已被证明适合 CoT 推理设置，或提供足够标签以构造显式推理轨迹。

  • NAVSIM 源自 nuPlan 驾驶日志，是大规模自动驾驶基准，为非反应式仿真规划评估提供真实世界数据。
  • ROADWork 面向道路施工区自动导航，包含临时标志、非常规车道配置、锥桶与护栏等动态障碍以及工人存在等标准驾驶基准中覆盖不足的场景。
  • Impromptu 是从八个开放驾驶数据集中蒸馏的大规模视觉-语言-动作基准，关注四类非结构化 corner-case，并提供面向规划的问答标注与轨迹数据。
  • Alpamayo-R1 引入 Chain of Causation 标注，包含与复杂驾驶行为对齐的决策依据推理轨迹，以增强 VLA 模型解释性和泛化能力。

5.2 CoT 标注构造

训练 OneVL 的关键挑战之一，是为每个驾驶场景获得高质量 CoT 推理标注。NAVSIM 上，本文使用 AdaThinkDrive 发布的 CoT 标注。这些标注提供自然语言推理轨迹，覆盖车道边界等场景解释、车辆和行人等关键对象分析，以及最终驾驶意图。它们由 VLM 从原始检测标签合成，作为语言辅助解码器 L_l 的监督目标。

ROADWork 上，作者使用类似的内部流程构造 CoT 标注。Impromptu 上，作者从原数据集问答对构建 CoT，并为 corner-case 轨迹预测补充显式决策与根因标签。Alpamayo-R1 上，作者使用公开 checkpoint 为所有训练样本预测 CoC 标签。这些标注监督语言辅助解码器，使模型在非结构化驾驶场景中学习稳健推理和决策逻辑。

5.3 实验设置

NAVSIM 使用 PDM score 评价，它联合衡量轨迹安全性、舒适性和进度。ROADWork 报告 ADE 与 FDE，用于衡量航点准确性。Impromptu 除 ADE/FDE 外，还按原论文协议报告前四秒轨迹预测 L2 error。Alpamayo-R1 同样报告 ADE 与 FDE。所有方法均报告平均推理时延。

本文比较两类基线，均基于 Qwen3-VL-4B-Instruct，并引入已有 SOTA 作为更强参考。自回归方法包括 AR Answer，即不使用推理、直接输出轨迹；以及 AR CoT+Answer，即先生成完整推理链再输出轨迹。潜在 CoT 方法包括适配驾驶任务的 COCONUT、基于自蒸馏的 CODI，以及带文本辅助解码器的 SIM-CoT。

在 NAVSIM 监督微调设置中，已有 SOTA 包括 AdaThinkDrive 和 LaST-VLA。ROADWork 上比较 YNet，Impromptu 上比较 Impromptu VLA，Alpamayo-R1 上比较基于 flow matching 的 Cosmos-Reason。AR 基线训练 2 个 epoch，学习率 4e-5，batch size 64；潜在 CoT 基线训练 6 个 epoch，学习率 4e-5，batch size 64。若未特别说明，已有 SOTA 结果直接取自文献。

5.6 既有潜在 CoT 方法在 VLA 驾驶中失败

除 Alpamayo-R1 外，三种适配的潜在 CoT 方法均显著低于 answer-only AR 预测。这说明为纯文本推理设计的语言潜在 CoT 方法不能有效迁移到多模态时空轨迹预测。它们定义的紧凑语言潜在空间不足以支持精确航点预测所需的几何推理。从智能压缩视角看，这种失败是根本性的：这些方法压缩的是场景语言描述，而语言本身已经是物理世界的抽象，编码语义标签与关系，却不编码决定未来结果的时空因果动态。换言之，它们满足压缩原则的效率条件，却不满足智能条件。

另一个可能因素是，这些基线没有使用 OneVL 的分阶段训练流程，因此在完整耦合优化开始时，它们的 latent 流可能尚未与轨迹和多模态监督充分对齐。OneVL 通过把压缩与验证结合克服这一限制：辅助解码器保证 latent bottleneck 保留空间和语言上有意义的内容，而不是坍缩为退化表示。三阶段训练也同样关键，因为它会在联合优化前逐步对齐 bottleneck。

5.7 显式 CoT 监督的收益

在 NAVSIM 上，AR CoT+Answer 的 88.29 高于 AR Answer 的 87.47，提升 0.80 PDM-score。这确认显式推理监督对轨迹预测有实际帮助，也建立了潜在 CoT 方法在降低时延时应接近的质量上界。ROADWork、Impromptu 和 Alpamayo-R1 中也能观察到类似趋势。

5.11 深入分析：收益来自何处

一个自然问题是，为什么 OneVL 的隐式潜在推理使用更少 token，却能优于显式 AR CoT+Answer。本文提出两个机制。

第一是压缩收益。紧凑 latent token 迫使模型把最相关于轨迹的推理蒸馏到小型表示瓶颈中，过滤无关或冗余内容。这正是信息瓶颈原则预测的机制。更强压缩会丢弃噪声，只保留对输出有预测力的因果特征，从而形成比冗长自由 CoT 更好的泛化表示。

第二是世界模型接地收益。视觉辅助解码器显式要求视觉 latent token 编码时空场景动态，即未来帧内容；这与轨迹预测直接相关。预测未来场景外观迫使 latent 内化交通参与者运动和道路几何的因果动态。显式语言 CoT 没有类似空间接地机制，它以符号方式描述世界，却把因果几何留在隐式层面。

视觉辅助解码器贡献 0.87，语言辅助解码器贡献 0.31，二者差异体现了视觉解码器的世界模型角色。自动驾驶轨迹预测本质是空间预测任务，视觉 token 重构，即预测 0.5 到 1.0 秒后的场景外观，提供与几何预测本质更一致的监督。语言 CoT 从抽象符号层面描述推理过程，对语义接地很有价值，但与决定轨迹结果的物理动态仍相隔一层。

预填充推理的速度优势来自现代 Transformer 对 prefill 序列的一次并行处理，而自回归解码需要顺序 token 生成。若只在 prefill 阶段增加少量 latent token，相比本就很长的图像 patch 序列，开销可以忽略。

既有潜在 CoT 方法在自动驾驶中失败，是因为它们假设潜在表示可从教师文本生成中压缩推理质量，但驾驶领域需要视觉世界模型监督。没有视觉辅助解码器，latent 只能编码语言层抽象，丢失精确轨迹预测所需的几何信息。另一方面，它们也缺少 OneVL 的三阶段训练流程，导致语言 latent、视觉 latent 与轨迹预测在优化初期没有对齐。OneVL 通过视觉辅助解码器提供精确空间监督，并通过三阶段训练避免优化冲突。

6 结论

本文提出 OneVL，一个面向自动驾驶轨迹预测的框架，其核心假设是：压缩驱动泛化。本文的关键贡献之一，是指出既有潜在 CoT 方法为何在规划任务上失败。压缩语言并不等同于压缩场景动态。驾驶场景的自然语言描述天然抽象，它编码语义标签，而不是决定未来结果的物理因果结构。因此，压缩语言满足压缩原则的效率要求，却不满足智能要求。

OneVL 通过引入视觉解码器形式的世界模型辅助来弥合这一差距。该解码器预测未来帧视觉 token。未来帧预测是具体且具有因果接地的压缩目标：能预期场景视觉演化的模型，必然已内化交通参与者运动与场景交互的动态，而这些信息仅靠语言无法可靠编码。

推理时，辅助解码器被丢弃，预填充 latent token 使模型以匹配 answer-only 预测的时延完成单次轨迹生成。三阶段训练流程对实现这种压缩至关重要：Stage 0 建立有意义 latent 表示，Stage 1 在稳定 latent 空间上对齐解码器，Stage 2 通过双向联合优化从两侧收紧 bottleneck。消融结果显示，跳过该课程会使压缩坍缩为记忆，并导致灾难性性能下降。

经验上，OneVL 在 NAVSIM、ROADWork、Impromptu 和 Alpamayo-R1 上获得 SOTA 结果，同时匹配 answer-only 推理速度。最值得注意的是，OneVL 是唯一超过显式自回归 CoT 的潜在 CoT 方法，直接证明当压缩同时由语言和世界模型监督接地时，更紧凑的表示能产生比逐 token 冗长生成更有效的推理。最后，通过追加轻量 MLP 回归头，OneVL 在仅 5% 原始时延下仍保持竞争性能，显示了高效真实部署的可能性。

局限

当前系统训练时需要约 3 倍显存，因为必须同时持有三个完整 4B 模型实例。虽然 DeepSpeed ZeRO-2 可以缓解这一问题，但基础设施要求仍然不低。此外，latent token 数量是经验选择的；系统研究 latent token 数量与表示容量之间的权衡，是后续工作。

未来方向

第一，虽然 OneVL 的预填充机制消除了 latent CoT 开销，轨迹 token 本身仍以自回归方式生成。第 5 节显示，追加 MLP head 可牺牲一定性能换取更高速度，但整体时延仍受 AR 解码约束。因此，通过并行或非自回归轨迹解码弥合这一差距，是面向安全关键驾驶系统实时部署的重要步骤。

第二，把世界模型解码器扩展到多相机输入，可支持 360 度未来场景预测和更完整因果场景理解，进一步增强视觉 latent 可用的压缩目标。第三，双模态解释框架可支持新型人机界面，使驾驶员实时获得车辆规划决策的视觉与语言理由。这不仅能提升透明度与信任，也有潜力为强化学习提供更丰富训练信号，闭合世界模型预测与策略改进之间的回路。

H 原论文公式与符号对齐说明

主模型损失 L_c 对轨迹答案 token 与 latent token 进行交叉熵监督；语言损失 L_l 要求语言辅助解码器在 Z_l 条件下重构真实 CoT token 序列；视觉损失 L_v 要求视觉辅助解码器在 Z_v 条件下重构未来帧离散视觉 token。三者合并时，lambda_l = 1.0，lambda_v = 0.1。较小的视觉权重并不表示视觉目标不重要，而是因为视觉 token 预测更难，若权重过大，可能在联合优化中压制轨迹与语言目标。

Z_l 和 Z_v 的形式都体现了 OneVL 的核心思想：辅助解码器不只读取 latent，也读取当前视觉上下文。语言解码器输入 [W_l(V), W_l(H_l)]，视觉解码器输入 [W_v(V), W_v(H_v)]。这意味着 latent 不是孤立摘要，而是在当前帧上下文中被解释和约束的中间表示。推理时这些解码器被移除，但训练期形成的约束会通过主模型参数和 latent 位置的隐藏状态保留下来。

预填充推理的关键在于区分 prefill 与 decode。prefill 阶段的所有 token 可并行处理；decode 阶段则必须逐 token 自回归生成。OneVL 把视觉和语言 latent 都放入 prefill，因此它们不产生逐步解码时延。模型只需在 decode 阶段生成轨迹 token。这正是 OneVL 可以接近 answer-only 时延的技术原因。

I 附录示例的中文释义

NAVSIM 示例中，标注首先指出自车所在车道右侧接近不可行驶区域，因此需要略向左行驶；随后识别前方约 18.42 米、左侧 0.49 米处的同向车辆，并指出其运动状态较快；最后给出决策：基于场景理解和导航信息，自车应保持速度并保持车道。

ROADWork 示例中，标注列出多个关键因素：路面前方橙色施工警示牌提示施工活动；左侧锥桶形成临时导流和车道收窄；右侧路边停放车辆压缩可通行空间；右侧脚手架或人行道施工提示正在作业。根因被总结为锥桶导流与停放车辆共同导致可用车道变窄，因此决策是纵向减速、横向保持导流车道。

Impromptu 示例中，决策标签为纵向停车、横向直行。原因是存在施工障碍与横穿道路的行人，车辆需要停车以保证安全并遵守交通规则。

Alpamayo-R1 示例较短，说明由于路口右转交通灯为绿色，因此应在路口右转。这类 CoC 标注强调决策与可观察因果条件之间的直接连接。
