1. 一句话结论

UniDrive-WM 的核心不是再加一个未来帧预测头，而是让“计划先于想象”：把 VLM 的 reasoning embedding 变成可微的连续动作 latent，并把 planning token/feature 放在未来图像 token 或 latent 之前，使生成器只能在动作条件下构造未来，从而用视觉未来的一致性反向约束规划。

1. 研究问题：为什么理解、规划和生成要统一

自动驾驶模型通常沿三条路线发展：纯感知/规划模型把相机输入直接映射到轨迹；语言模型路线擅长解释和问答，却经常把规划当成最后一个回归头；世界模型路线能够预测未来图像，但动作与生成可能互不相容。UniDrive-WM 观察到，驾驶员在“前方有行人、需要减速并保持车道”这样的场景中并不是先独立生成一张漂亮图片，再事后猜轨迹，而是先形成关于风险和动作的内部推理，再想象该动作会造成的未来。模型因此必须共享一个能同时表达语义、动作和视觉未来的空间。

论文将当前状态记为 s_t，它包含多视角图像、历史上下文和感知特征；高层语言条件记为 l；未来 waypoint 动作段记为 a_{t:t+m}；未来状态的一部分是未来前视图像。联合目标可以写成：

{s^t+n,a^t:t+m}∼Pθ(s1:t,a1:t−1,l)\{\hat{s}_{t+n},\hat{a}_{t:t+m}\}\sim P_\theta(s_{1:t},a_{1:t-1},l){s^t+n​,a^t:t+m​}∼Pθ​(s1:t​,a1:t−1​,l)

公式解释：模型不是只预测一个 a_t，而是在历史状态和指令条件下共同建模未来状态与动作段；n 是未来帧的时间偏移，m 是 waypoint 数量。

为了让这个联合分布可训练，论文给出条件分解：

a^t:t+m∼Pθ(at:t+m∣st,l),s^t+n∼Pθ(st+n∣st,a^t:t+m,l)\hat{a}_{t:t+m}\sim P_\theta(a_{t:t+m}\mid s_t,l),\qquad \hat{s}_{t+n}\sim P_\theta(s_{t+n}\mid s_t,\hat{a}_{t:t+m},l)a^t:t+m​∼Pθ​(at:t+m​∣st​,l),s^t+n​∼Pθ​(st+n​∣st​,a^t:t+m​,l)

第一项说明规划受当前视觉、历史与语言影响；第二项说明未来状态必须接受预测轨迹的条件。图 1 把这件事画成四个区域：输入与记忆、统一 VLM、动作规划、两种未来图像解码器。它还标出训练时的 GT 边界，因为未来真实图像只在训练中可见，部署时只能依赖模型自己的动作和当前观测。

证据定位：论文 Introduction、Method §3 总体建模；图 1/2；训练细节见 arXiv HTML lines 626--656。

2. 机制一：QT-Former 把多视角视频变成可记忆的场景接口

UniDrive-WM 没有让 Vicuna 直接读取所有像素。它继承 ORION 的 QT-Former，用可学习 query 作为固定容量的“接口协议”。scene queries 负责建立场景级摘要，perception queries 承载检测、车道、交通灯和运动预测所需的结构化信息，history queries 则把过去帧压缩到可循环更新的 memory bank。这样做解决了两个工程矛盾：相机数量和历史长度可以变化，但语言模型的上下文入口必须稳定；规划需要几何关系，而语言模型更擅长在紧凑 token 上推理。

当前多视角图像经过 EVA-02-L 得到特征 F_m，同时加入 3D positional encoding。query 先做 self-attention 交换对象与场景关系，再做 cross-attention 读取图像特征。附录给出的历史更新写成：

Qh=CA⁡(Qh,M+Pt,M+Pt),Q^h=CA⁡(Qh,Qs,Qs)Q_h=\operatorname{CA}(Q_h,M+P_t,M+P_t),\qquad \hat Q_h=\operatorname{CA}(Q_h,Q_s,Q_s)Qh​=CA(Qh​,M+Pt​,M+Pt​),Q^​h​=CA(Qh​,Qs​,Qs​)

这里 Q_h 是当前历史 query，M 是旧记忆，P_t 是当前位置编码；第二个 cross-attention 让历史 query 从 scene queries 读取当前场景摘要。

M=[Q^ht−n+1,…,Q^ht−1,Q^ht]M=[\hat Q_h^{t-n+1},\ldots,\hat Q_h^{t-1},\hat Q_h^t]M=[Q^​ht−n+1​,…,Q^​ht−1​,Q^​ht​]

这条式子规定了时间方向，最新帧在右端，memory bank 超过窗口后丢弃最早帧。训练时感知 queries 进入 critical-object detection、lane detection、traffic state 和 dynamic-motion heads；3D 检测采用 Hungarian bipartite matching，分类用 focal loss，框回归覆盖中心、尺寸、yaw 与速度的 L1 项。联合训练时预训练 QT-Former 初始化，detection head 冻结，使该分支成为稳定的结构化视觉编码器。

一个具体例子是“左前方车辆突然减速”：当前帧的 perception query 编码该车 3D box 与速度，history query 通过 memory 保留其上一帧位置，LLM 因而能区分“静止路边车辆”和“正在横向切入的车辆”。如果没有 memory，两个瞬时图像可能语义相似，但规划器看不到速度变化；如果把所有历史像素直接拼接，序列长度会迅速超过 VLM 可承受范围。

实现边界：论文公开了 query 数量、记忆窗口和损失类型，但没有公开 QT-Former 的 Python 类名、hidden size、attention head 数或具体 batching 代码；图 2 是论文接口级结构。

3. 机制二：latent trajectory planner 将语言推理接到连续动作

直接用 language feature 回归 waypoint 往往会出现“语义正确、几何不平滑”：模型知道应该绕开障碍，却无法稳定地输出一串连续二维点。UniDrive-WM 引入 latent action variable，把 VLM 的高层状态 h_VLM 映射成高斯分布，再用轻量 recurrent waypoint decoder 逐点生成 BEV ego frame 中的轨迹。

qϕ(za∣hVLM)=N(μh,σh2)q_\phi(z_a\mid h_{VLM})=\mathcal N(\mu_h,\sigma_h^2)qϕ​(za​∣hVLM​)=N(μh​,σh2​)
za=μh+σh⊙ϵ,ϵ∼N(0,I)z_a=\mu_h+\sigma_h\odot\epsilon,\qquad \epsilon\sim\mathcal N(0,I)za​=μh​+σh​⊙ϵ,ϵ∼N(0,I)

第一式把动作表示成分布而不是单点；第二式是 reparameterization trick，使采样过程对 mu_h 和 sigma_h 可微。直观上，mu_h 表示典型驾驶意图，sigma_h 表示仍未确定的动作自由度。

a^t:t+m={(x^i,y^i)}i=1m\hat a_{t:t+m}=\{(\hat x_i,\hat y_i)\}_{i=1}^{m}a^t:t+m​={(x^i​,y^​i​)}i=1m​
Lplan=Lcol+Lbd+LmseL_{plan}=L_{col}+L_{bd}+L_{mse}Lplan​=Lcol​+Lbd​+Lmse​

L_col 惩罚轨迹与动态物体 3D boxes 相交，L_bd 惩罚越过可行驶区域或实线边界，L_mse 让 waypoint 接近专家轨迹。与 ORION 的显式 reasoning-token/GT-trajectory Gaussian KL 不同，UniDrive-WM 联合多模态训练时去掉显式 KL；作者认为强行把 VLM latent 压到标准正态会让语言、动作和图像三种目标互相拉扯，训练不稳定。

例如车辆在无保护左转路口面对一辆横穿自行车。L_mse 鼓励轨迹贴近专家的减速—等待—转弯曲线，L_col 在自行车 box 与候选点相交时提高代价，L_bd 防止为了绕行而压过实线。三项共同作用，才把“应该让行”转化为可执行的连续点序列。

4. 机制三：离散 AR 将动作条件写入视觉 token 链

离散分支扩大 VLM 的联合 codebook，使语言 token 与 image token 可以在同一自回归序列中出现，并加入 <image_start>、<image_end> 边界。最关键的顺序是 planning token 紧随当前 reasoning、位于 image token 之前；这使每一个未来视觉 token 都能看到计划，而不是让图像生成器先自由想象再补动作。

Z=ZL+ZIZ=Z_L+Z_IZ=ZL​+ZI​

Z_L 是语言 codebook，Z_I 是视觉 codebook；“相加”表示统一词表/嵌入空间，不代表把语言文本逐像素相加。

Pθ(q1:H⋅W∣st,at:t+m)=∏i=1H⋅WPθ(qi∣q<i,st,at:t+m)P_\theta(q_{1:H\cdot W}\mid s_t,a_{t:t+m})=\prod_{i=1}^{H\cdot W}P_\theta(q_i\mid q_{<i},s_t,a_{t:t+m})Pθ​(q1:H⋅W​∣st​,at:t+m​)=i=1∏H⋅W​Pθ​(qi​∣q<i​,st​,at:t+m​)

论文给出的 AR 目标未来图像分辨率为 192×128。分辨率低是有意的表示取舍：离散 token 对语义稳定、训练和闭环延迟友好，但空间 token 数随 H×W 增长，LLM 的上下文注意力成本近似按 O(N²) 增长。MoVQGAN 解码器把视觉 token 恢复成图像；其具体 codebook 大小和实现类名没有在官方仓库公开，报告不作补写。

从实现角度，训练批次至少要同时携带当前上下文、动作 token、未来图像 token 和 shift-right 标签序列；推理循环则在遇到 <image_end> 或达到 H×W 后停止。这是接口级契约，因为仓库没有 tokenizer、codebook 或生成循环文件。

5. 机制四：AR+Diffusion 用连续 latent 解耦分辨率

连续分支保留 AR transformer 的语义和动作条件，但不要求 LLM 逐像素生成长 token 链。它追加 64 个 learnable latent query tokens，让 transformer 先输出紧凑的连续图像 latent，再由 diffusion decoder 解码到 512×1024 的未来帧。论文明确冻结 vision encoder，只训练 diffusion decoder，并使用 deterministic reconstruction；因此它牺牲随机多样性换取驾驶几何的稳定性。

X0∼N(0,1),t∼Uniform⁡(0,1),Xt=tX1+(1−t)X0,Vt=X1−X0X_0\sim\mathcal N(0,1),\quad t\sim\operatorname{Uniform}(0,1),\quad X_t=tX_1+(1-t)X_0,\quad V_t=X_1-X_0X0​∼N(0,1),t∼Uniform(0,1),Xt​=tX1​+(1−t)X0​,Vt​=X1​−X0​
LFM=E[∥Vθ(Xt,Q,t)−Vt∥22]L_{FM}=\mathbb E\left[\left\|V_\theta(X_t,Q,t)-V_t\right\|_2^2\right]LFM​=E[∥Vθ​(Xt​,Q,t)−Vt​∥22​]

这不是让网络直接猜像素，而是学习从噪声端指向真实 latent 的 vector field。Q 是 64 个 latent queries 以及动作/场景条件，t 告诉 decoder 当前位于路径的哪个位置。

LCLIP=1−⟨Eclip(Ipred),Eclip(Igt)⟩∥Eclip(Ipred)∥2∥Eclip(Igt)∥2L_{CLIP}=1-\frac{\langle E_{clip}(I_{pred}),E_{clip}(I_{gt})\rangle}{\|E_{clip}(I_{pred})\|_2\|E_{clip}(I_{gt})\|_2}LCLIP​=1−∥Eclip​(Ipred​)∥2​∥Eclip​(Igt​)∥2​⟨Eclip​(Ipred​),Eclip​(Igt​)⟩​

CLIP 项约束语义相似性，flow matching 项约束连续生成路径。连续 latent 的长度不随输出像素面积平方增长，所以能够保持高频几何；代价是 decoder 计算重，A100 上只有 0.4 fps。

在“前车刹车、道路边界清晰”的样本上，离散 AR 可能快速给出语义正确但纹理模糊的前视图；连续分支可以在相同 planning feature 下恢复车道线、车辆轮廓和远处信号灯的高频几何。由于推理确定性，重复相同输入会得到更稳定的画面，但不会表达多个合理未来。

6. 机制五：planning→generation 的因果排序与双向训练信号

论文的关键因果设计是 planning token/feature 直接位于 image token 或连续 latent 之前。信息流从当前观测经过 VLM 到动作，再从动作条件化未来图像；梯度流则从 L_plan、L_CE、L_FM 和 L_CLIP 回到共享的 VLM 表示。未来图像监督反哺规划是训练阶段的辅助信号，不是部署时把真实未来塞进模型。

pθ(I^t+n∣st,hVLM)=pθ(I^t+n∣st,a^t:t+m,hVLM)p_\theta(\hat I_{t+n}\mid s_t,h_{VLM})=p_\theta(\hat I_{t+n}\mid s_t,\hat a_{t:t+m},h_{VLM})pθ​(I^t+n​∣st​,hVLM​)=pθ​(I^t+n​∣st​,a^t:t+m​,hVLM​)

实验把顺序反过来做了对照：Generation + Planning 的 Avg. L2 为 0.67 m、collision 0.45%、FID 9.1；Planning + Generation（本文）为 0.64 m、0.43%、FID 7.2。差异同时出现在轨迹和图像，说明顺序影响动作与未来的一致性。

这个机制也解释了为什么图像生成会改善 VQA。VQA 消融中，去掉图像生成时 CIDEr/BLEU/ROUGE-L 为 65.7/52.4/77.5，加入后为 66.7/53.5/78.6；未来预测迫使共享表示保留“会影响未来的对象和关系”，而不仅是回答当前帧的表面词汇。

7. 机制六：两阶段联合目标如何闭合训练

AR 模式的总损失是：

L=LCE+LplanL=L_{CE}+L_{plan}L=LCE​+Lplan​

其中 L_CE 是未来视觉 token 的 teacher-forcing cross entropy。AR+Diffusion 额外加入连续生成与语义对齐：

L=LCE+Lplan+LFM+LCLIPL=L_{CE}+L_{plan}+L_{FM}+L_{CLIP}L=LCE​+Lplan​+LFM​+LCLIP​

Stage 1 用 driving 数据端到端联合优化规划和未来图像，LLM 采用 LoRA；AR 分支在 planning token 后接 image-start，连续分支在 planning features 后接 64 个 latent queries。Stage 2 混入 VQA 与 driving 数据，继续优化问答、轨迹和未来图像，使 vision-language-planning space 不因单一任务而漂移。

多任务 batch 必须使用标签掩码：VQA 样本没有未来图像 token，driving 样本没有问答答案，因此每个 loss 只对其存在的标签计算。论文没有公开 optimizer、学习率、随机种子和梯度累积策略，不能从图中推断这些超参数。联合训练去掉显式 KL 也意味着 latent 尺度由多项任务共同决定，复现时应监控各 loss 的量纲和梯度范数。

8. 实现解剖一：论文级 Algorithm 1 契约（非官方源码）

由于官方仓库没有 Python 文件，本节把论文方法改写成可执行者可以据此重建的接口级伪代码。它明确每个张量何时产生、哪一项 loss 使用哪一类标签，以及训练和推理在哪里分叉；它不是声称存在同名类或函数。

输入：多视角帧 I[t-n+1:t]，语言 l，未来帧 I[t+n]（训练时）
1. F_m ← VisionEncoder(I)；加入 3D 位置编码
2. Q_s,Q_p,Q_h ← QueryFormer(F_m, memory)
3. perception ← heads(Q_p)；更新 memory ← append(Q_h)
4. h ← VLM(Q_s, perception, history, l)
5. z_a ← reparameterize(q_phi(z|h))
6. waypoints ← recurrent_decoder(z_a,h)
7. 若 AR：规划 token 后 teacher-force 未来视觉 token
8. 若 AR+Diffusion：规划 feature 后接 64 latent queries
9. 计算 L_plan；按分支计算 L_CE 或 L_FM+L_CLIP
10. Stage 2 对 VQA batch 计算语言 loss
11. mask 不存在的标签，汇总有效 loss
12. 反传共享 VLM 与可训练 decoder；冻结边界按论文设定执行

伪代码中最容易被误读的是第 7--8 步：AR 并不是先生成完整图片再规划，连续分支也不是独立 diffusion 模型。两者都共享 VLM 的动作条件，只是视觉表示分别采用离散 token 和连续 latent。第 11 步的 mask 对复现尤其重要，否则 VQA 样本会被错误地当成缺失未来帧，导致损失尺度偏移。

源码证据：官方仓库 `index.html:130-139` 的 Code 链接为 `#` 且显示 “Code (Coming Soon)”；仓库 HEAD 递归树 42 个路径中没有 `.py/.yaml/.ckpt/.safetensors`。因此本节仅引用 TeX 方法与论文接口。

9. 实现解剖二：训练/推理张量链与 GT 边界

把训练和部署画成两条平行链，可以看出世界模型的监督边界。训练链拥有专家 waypoint、未来真实图像和 VQA 答案；推理链只有当前多视角帧、历史 memory、语言指令和模型自己的上一步输出。AR 推理逐 token 生成直到 image-end；AR+Diffusion 推理使用确定性连续重建，二者都不读取真实未来。

张量契约的工程含义是：历史 memory 的时间轴必须与当前帧对齐，waypoint 必须在 ego BEV 坐标中表达，未来图像目标必须与动作段时间偏移 n 一致。任何错位都会产生“看起来能训练、部署却不一致”的假象。例如把右后视图误当成前视目标，FID 可能仍下降，但规划 token 与生成画面不再表达同一驾驶未来。

10. 实现解剖三：官方源码状态、可复现边界与诚实替代

源码审计得到一个必须明确写出的结论：UniDrive-WM 的官方 GitHub 目前是论文项目页，而不是算法实现。仓库 `master` 的固定提交为 `68e48c1...`，只有 `index.html`、README、静态 CSS/JS、论文 PDF、PNG/PDF 图、视频和模板配置；完整七次提交历史也没有训练脚本、推理脚本、数据预处理、配置、权重或 checkpoint。GitHub 组织公开仓库数为 1，tags/releases 为空；两个开放 issue 分别询问 checkpoint 和代码发布时间，均没有发布附件。

附加工程推演：从论文符号到可运行系统

1. 时间对齐、坐标系与标签契约

论文中的 t 不是装饰下标，它约束所有数据的对齐。当前输入窗口 I_{t-n+1:t} 的最右帧必须是决策时刻；memory 中最旧的 query 对应窗口左端，未来目标 I_{t+n} 必须和专家动作段的时间基准一致。waypoint 使用 ego BEV 坐标，车辆自身位于原点且前进/横向方向固定；若预处理把世界坐标直接交给 decoder，车辆转向时同一路段会呈现不同数值分布，模型学到地图朝向而不是驾驶行为。

一个稳健 batch 应保存帧时间戳、相机内外参、ego pose、3D box 速度、语言指令、waypoint 标签和未来图像索引。QT-Former 的 3D positional encoding 依赖几何量，collision/boundary loss 也依赖同一坐标系。论文没有公开 data loader，因此这些字段是由公式推导的实现契约，不是官方代码事实。

2. 为什么 query 数量会改变系统行为

scene queries=512、perception queries=600、history queries=16 不只是模型规模。query 是固定容量瓶颈：600 个 perception slots 在检测对象、车道、信号状态和运动信息间分配注意力；16 个 history slots 把每帧动态摘要压缩进 memory bank。对象数超过 slots 时，注意力必须选择与任务相关的目标。slot 过少会漏掉远处小目标，过多又增加 cross-attention 显存与噪声；论文给出的是选定配置，不代表普适最优。

3. latent planner 的不确定性与稳定性

sigma_h 让模型能够表达多个合理动作，但论文最终输出一条 recurrent waypoint 序列，而不是显式多候选集合。训练时重参数化把随机性留在 latent，碰撞与边界损失把不安全样本的概率质量压低。去掉显式 KL 后，sigma_h 不再被强迫接近 1；它可能携带场景尺度，也可能在联合训练中退化。复现时应检查 latent 均值/方差、轨迹曲率和碰撞梯度，不能只看总 loss。

4. 离散与连续表示的共同条件、不同代价

AR 与 AR+Diffusion 都从相同 reasoning embedding 读取场景和语言，都先接收 planning 条件，再产生未来视觉。差异在中间表示：AR 把网格展平成离散序列，teacher forcing 稳定但带来 exposure bias；连续分支把语义压进 64 个 latent queries，避免高分辨率 token 爆炸，却引入更重的向量场回归。部署预算只有几百毫秒时，2 fps 的 AR 更现实；若任务是离线未来几何评估，0.4 fps 连续分支换来的 FID 和分辨率更有价值。

5. 失败模式与可诊断信号

第一类失败是动作—图像不一致：轨迹绕开障碍但生成帧仍正面撞向障碍，通常是 planning token 顺序错误或时间索引错位。第二类是记忆漂移：连续帧同一车辆被识别成不同对象，常见原因是 memory 更新顺序或 pose 错误。第三类是梯度竞争：VQA loss 降低而 L_plan 变差，可能是 Stage 2 标签 mask 或归一化错误。第四类是连续 decoder 语义正确但几何模糊，表现为 CLIP 相似度高而车道线断裂，此时必须分别检查 L_FM 与 L_CLIP。

6. 复现清单与证据等级

公开材料能够约束输入输出语义、四类 query、16 帧记忆、latent action 公式、三项规划损失、两条视觉路径、四项总损失、两阶段训练与评测指标。公开材料无法约束 tokenizer/codebook、Vicuna 投影层、QT-Former hidden size/head 数、optimizer/学习率/seed、扩散 decoder 层数与采样策略、data loader 和 checkpoint。把这两类信息分开，读者才能知道哪些结果可以逐项对照，哪些必须由重实现者重新验证。

机制联读：为什么这些模块必须同时存在

如果只保留 VLM 和 waypoint head，模型可以描述“前方有施工”却没有稳定的未来视觉约束；如果只保留生成器，模型可能画出视觉上合理的道路，却无法保证画面对应一条可执行轨迹。QT-Former 提供几何事实，VLM 提供语言和因果推理，latent planner 提供连续动作，未来生成器则把动作翻译成可观察的后果。四者不是并列插件，而是同一条件分布的不同投影。

从梯度角度看，L_plan 让 reasoning embedding 对碰撞、边界和专家曲线敏感；L_CE 或 L_FM 让该 embedding 还能解释未来外观；L_CLIP 防止连续 decoder 只拟合低层像素而丢失场景语义；VQA loss 则要求共享表示能用语言复述对象、动作和关系。任何一项被移除，消融表中都会出现对应退化：无 detection 时 3 秒 L2 从完整模型的 1.079 增至 2.146，无 image generation 时规划误差和 VQA 质量也同时变差。

对新手来说，可以把训练样本理解成一条带答案的因果链：当前帧告诉模型“现在发生什么”，语言告诉模型“任务是什么”，专家 waypoint 告诉模型“应该怎么走”，未来帧告诉模型“这样走会看到什么”。UniDrive-WM 的贡献在于让四种答案进入同一个前向图，并用 planning-first 顺序防止未来视觉脱离动作。部署时只删除答案端，保留同样的计算顺序。

从数值到判断

表格中的 0.241 m、0.589 m、1.066 m 是不同预测时域的位移误差，不是概率；collision 0.192、0.426、0.657 是百分比指标，不能与 L2 直接相加。FID 6.6 只衡量未来帧分布接近程度，NDS 0.755 反映感知综合质量，DS/SR 则是闭环驾驶评价。报告把它们分栏，是为了避免把跨量纲的数字误读为一个总分。

还要注意摘要中的相对提升和表中的绝对值不同。以 closed-loop Avg. L2 为例，AR+Diffusion 是 0.63 m，ORION 是 0.68 m；这可以计算绝对差 0.05 m，但不能把项目页的 5.9% 和 v4 的 7.3% 当成同一实验版本。版本、数据集和评测协议必须跟着数字一起记录。

12. 讨论、限制与未来工作

作者明确的未来工作是更交互、更长时域的驾驶场景，并加速 AR+Diffusion。当前短路线 closed-loop 与 0.4 fps 连续解码说明系统仍处在“高保真想象”和“实时控制”之间的折中点。AR 的离散瓶颈限制高分辨率，连续分支的确定性解码降低了多样性；两者都没有在论文中展示显式多候选轨迹搜索。

独立地看，Bench2Drive 主要是受控/合成环境，44 个交互场景不能代表所有长尾道路事件；nuScenes 的 open-loop 不能替代长期闭环安全验证。QT-Former detection head 在联合训练中冻结，使感知接口稳定，但也限制了端到端共同适应的空间。未来图像监督以目标前视帧为主，对侧向和全景未来的覆盖仍有限。最后，官方代码尚未发布，复现者无法核对数据采样、optimizer、随机种子、latent 归一化和 decoder 细节。

这些限制不否定方法的贡献，而是界定结论适用范围：论文证明了统一表示与动作先行的设计在两个数据集和多个任务指标上有一致收益；它没有证明一个固定的 deterministic future frame 就能覆盖真实驾驶的全部不确定性。

实践建议：如何验证一个重实现没有偏离论文

第一步先做最小张量单测：给定两帧合成场景，检查 memory 的时间顺序、query 数量和 ego 坐标 waypoint；第二步只训练 planning head，确认碰撞、边界与 MSE 能分别响应构造样本；第三步加入离散 AR，检查 planning token 是否真的出现在 image-start 前；第四步再加入连续分支，分别监控 flow matching 与 CLIP loss。不要一开始端到端训练所有任务，否则坐标错位、标签 mask 和 decoder 问题会混在同一条 loss 曲线中。

验证未来生成时，应同时看三类证据：像素/分布指标、动作一致性和时序一致性。低 FID 但轨迹与画面冲突不能通过；单帧逼真但车辆身份在连续预测中跳变也不能通过。验证规划时则要在平均 L2 之外检查碰撞、车道边界、急转曲率和不同交互类别。论文附录的 merging、overtaking、emergency brake、give way、traffic sign 指标可以作为分层测试模板。

最终对齐应记录固定论文版本、数据 split、输入 resize、输出分辨率、query 数、memory 长度、LoRA rank/alpha、冻结模块和硬件速度。若实现者选择了论文未说明的 optimizer、学习率或 diffusion 步数，必须标成独立实现选择，并通过消融说明它们对结果的影响。只有这样，“基于论文重实现”才不会被误写成“官方代码复现”。

还应把每次验证的中间产物保存下来：输入 batch 的时间戳与 pose、QT-Former 的 query 统计、planner 输出的 waypoint 曲率、未来帧的 FID/CLIP 结果，以及 VQA 的有效标签数量。这样，当结果突然变差时，可以定位是视觉编码、历史记忆、动作 latent、生成 decoder 还是多任务 mask 的问题，而不是只看到一条无法解释的总损失曲线。对安全相关样本，建议额外记录与动态 box 的最小距离、越界次数和急刹车比例；这些诊断量不在论文主表中，却是判断“动作先行”是否真正落地的必要工程证据。

AR 的 teacher forcing 在训练时把真实的前一个视觉 token 提供给模型，推理时却只能使用自己的预测，因此会积累 exposure bias；这也是离散分支在长序列和高分辨率下容易出现细节漂移的原因。连续分支不逐 token 展开图像，而是让 flow matching 在不同 t 上学习同一个 latent 速度场，减少了离散序列误差传播，但把稳定性压力转移到 latent 归一化、确定性解码和向量场覆盖范围。两条路径的差异应在复现日志中分别记录，不能只比较最终 FID。

实验解读还必须遵守证据等级：论文直接报告的数值是一级证据，图表之间的相对比较是二级解释，关于“未来监督导致规划改善”的因果判断则依赖模块和顺序消融，属于受控但有限的证据。没有官方训练源码和 checkpoint 时，任何重实现的提升都不能回填成论文原始结果；应同时报告自己的配置、随机种子和失败样本。这样的分层记录让读者能够复核结论，也能清楚知道 UniDrive-WM 当前真正公开了什么。

13. 结论：把未来想象变成可检查的驾驶计划

UniDrive-WM 的主线可以压缩成四个动作：QT-Former 将视频变成有时间记忆的场景接口；VLM 将视觉、历史和语言合成 reasoning embedding；latent planner 将推理变成可微的连续 BEV 轨迹；planning-first 的 AR 或 AR+Diffusion 再把这条轨迹落实为未来图像。联合损失和两阶段训练让信息流与梯度流闭合，实验则显示规划、生成、VQA 和感知之间存在可测量的互补。

对新手而言，最重要的判断标准不是“图像是否逼真”，而是生成的未来是否与动作相容：如果模型说要让行，未来帧中就应该出现减速后的空间关系；如果图像预测改善了，它是否同时降低碰撞和轨迹误差。对工程实现者而言，最重要的诚实边界是：当前能复现的是论文规定的接口和训练目标，不是官方仓库中尚不存在的类和脚本。

最终记忆点：UniDrive-WM 让规划先于未来视觉生成，因而未来图像不再是独立的“想象结果”，而成为检验动作是否自洽的辅助世界模型。
