With `--train.vla-finetune-alpha 0` the VLA is frozen; with `α > 0` the VLA is co-finetuned using a weighted flow-matching loss (matching the paper's `L_ro + α · L_vla` objective).95 96Example command (see `exp/stage1.sh`):97 98```bash99CHECKPOINT_DIR="$HOME/.cache/openpi/openpi-assets/checkpoints/pi05_droid_pytorch/model.safetensors"100 101python scripts/train_rl_token.py \102    --train.vla-config-name pi05_droid_finetune \103    --train.vla-checkpoint-dir "$CHECKPOINT_DIR" \104    --train.vla-finetune-alpha 1.0 \105    --train.batch-size 32 \106    --train.num-train-steps 5000 \107    --repo-id local/stack_the_blocks_100 \108    --data-transforms-fn rlt_openpi.policies.franka.config.three_camera_droid109```110 111Swap `--repo-id`, `--data-transforms-fn`, and the VLA config/checkpoint for your own dataset and robot.112 113Key flags (full list in `src/rlt_openpi/training/config.py::RLTokenTrainConfig`):114 115| Flag | Purpose |116| --- | --- |117| `--train.vla-finetune-alpha` | `0.0` = frozen VLA (only encoder/decoder trained); `> 0` = joint finetune. |118| `--train.num-train-steps` | Default `5000`. |119| `--train.batch-size` | Default `32`. |120| `--train.warmup-steps` | Linear LR warmup, default `500`. |121| `--train.resume-checkpoint` | Resume from a previous `rl_token_step<N>.pt`. |122| `--train.save-every` | Checkpoint interval (default `1000`). |123| `--repo-id` | LeRobot dataset ID. |124| `--data-transforms-fn` | Import path to a data-transform factory (e.g. `rlt_openpi.policies.franka.config.three_camera_droid`). |125 126Outputs land under `checkpoints/rl_token/<run_name>/rl_token_step<N>.pt`, where `run_name` defaults to `run_YYYYMMDD_HHMMSS`.127 128---129 130## Stage 2: Online RL131 132With VLA + encoder frozen, a lightweight **Actor** and **Twin-Q Critic** are trained online. The actor conditions on `(z_rl, VLA reference action chunk)` and outputs a **residual** over the VLA's proposal (zero-initialized last layer, so the actor starts as a copy of the VLA). The loop first runs a **warmup phase** collecting episodes with the base VLA policy, then alternates between rollout collection and off-policy TD3-style updates at UTD = 5, with a BC regularizer pulling the actor toward the VLA reference and reference-action dropout. A human supervisor provides sparse success/failure/progress rewards and can take over the robot via a VR controller mid-episode; interventions are stored in the replay buffer as corrective labels.133 134### Example hardware (Franka + DROID + VR)135 136The example `--env-factory` and `--intervention-factory` target:137 138- Franka Panda driven by the DROID stack (joint-velocity control).139- Three ZED cameras matching the layout expected by `three_camera_droid`.140- Oculus/VR controller wired into `src/rlt_openpi/envs/franka/intervention.py` (`make_vr_intervention`).141 142To run against a different robot or simulator, implement your own `make_env` / `make_intervention` callables (see the Franka example as a template) and pass their import paths via `--env-factory` and `--intervention-factory`.143 144### Example command (see `exp/stage2.sh`)145 146```bash147python scripts/train_online_rl.py \148    --env-factory rlt_openpi.envs.franka.env_factory.make_franka_env \149    --intervention-factory rlt_openpi.envs.franka.intervention.make_vr_intervention \150    --vla-config-name pi05_droid_finetune \151    --vla-checkpoint-dir checkpoints/pi05_droid_pytorch/model.safetensors \152    --rl-token-checkpoint checkpoints/rl_token/rl_token_step3000.pt \153    --task-prompt "stack the three blocks on the tray" \154    --warmup-steps 250 \155    --chunk-length 5 \156    --max-episode-chunks 150 \157    --save-dir checkpoints/online_rl158```159 160Key flags (full list in `src/rlt_openpi/training/config.py::OnlineRLTrainConfig`):161 162| Flag | Purpose |163| --- | --- |164| `--env-factory` | Import path to a `make_env` callable. |165| `--intervention-factory` | Import path to a `make_intervention` callable.
