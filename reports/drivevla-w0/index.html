§ 1. 核心研究问题 — "监督缺失"究竟是什么

1.1 研究背景与动机(作者明写的三个矛盾)

作者在 §1 L4-L12 列出的行业现状 + 矛盾:

  1. Scaling Law 假设 vs 驾驶领域现实(§1 L4):Kaplan 2020 / Zhai 2022 / Dehghani 2023 等工作在 NLP / ViT 领域实证了 power-law 数据 / 参数 scaling,驾驶领域自然希望复刻这个路径,但目前两大范式各有卡点。
  2. BEV 专用模型的先天劣势(§1 L5-L7):UniAD / VAD / BEVFormer 基于严格的 BEV 几何先验,难以利用非驾驶数据,架构紧凑限制了 large-scale scaling。
  3. VLA 的"形似实空"(§1 L8-L12):VLA 模型(ORION / ReCogDrive / AutoVLA)靠继承 VLM 的互联网级预训练参数,但 fine-tune 时只用 expert action(即几个 waypoint 的坐标)做监督 —— 对 7B 参数的模型来说,这是把"高维感官输入 → 几个低维控制信号"的映射,绝大多数内部表征容量根本没被激活。

作者原文关键判断(§1 L10-L12)翻译:这不是数据量问题,是监督信号的维度 × 密度问题。作者进一步观察到:在没有足够监督的情况下,大 VLA 模型甚至会跑输小的 BEV 专用模型(§1 L12,后面 Table 5 VLA-VQ 7B 在 NuPlan→NAVSIM 确实只有 62.2 PDMS,而 TransFuser-50M 在 scratch 就有 79.2 PDMS)。

1.3 创新性与贡献边界(严格拆)

作者声称的 3 个核心贡献(§1 L26-L32):

  • 贡献 1(概念):首次把 VLA 的训练瓶颈命名为 "supervision deficit",并给出数据扩展实验证明纯 action 监督在 70M 帧规模必然饱和(实证贡献,不是理论定理)
  • 贡献 2(方法):在两种 VLA 范式(VQ / ViT)下同时实例化 WM,而非只做其中一种;且明确区分 current-frame prediction(VQ)和 future-frame prediction(ViT)这一几乎没人关注的设计差异
  • 贡献 3(工程):MoE Action Expert + 揭示 decoder scaling 反转 —— 这条对工业部署格外重要,因为"大规模数据下简单 AR decoder 反而更强"和当下社区的"flow matching/diffusion 决策头是未来"的舆论相反
Warn

批判:贡献 1 的 supervision deficit 概念并非全新。LAW(Li 2024a ICLR 2025)已提出 latent world model 解决"感知弱监督";UniVLA / WorldVLA 把 action 纳入 AR 预测是同一思路。真正新颖的是把 WM 定位成"训练时辅助目标、推理时丢弃"的正则化器(§3.2 L51-L52 / L67-L68 明确),以及大规模数据下的系统实证。

2.3.1 AR World Model(VQ 路径,§3.2 L41-L53)

核心机制:让 VLM 以自回归方式生成当前图像 V_t 的所有 visual token (v_1, ..., v_N),以前序上下文 S_{<V_t} 为条件:

LWA=−∑i=1Nlog⁡P(vi∣S<Vt,v<i)L^\mathrm{WA} = -\sum_{i=1}^{N} \log P(v_i \mid S_{<V_t}, v_{<i})LWA=−i=1∑N​logP(vi​∣S<Vt​​,v<i​)

(其中 L_WA = L_WM-AR;记号改成上标是为了飞书公式稳定渲染)

联合优化:

Ltot=Lact+α⋅LWAL^\mathrm{tot} = L^\mathrm{act} + \alpha \cdot L^\mathrm{WA}Ltot=Lact+α⋅LWA

(L_tot = L_Total,L_act = L_Action,L_WA = L_WM-AR)

推理时:完全跳过 visual token 的自回归 sample,直接跳到动作生成,零额外开销。只在可视化需要时才真的采样 visual token 并经 MoVQGAN decode 回图像 Î_t。

代码里的关键发现(Phase 3):

  • --apply_loss_on_only_vision True 在所有 Stage 1+2 脚本都传
  • Stage 1 vision_loss_weight = 1.0(configs/moe_fast_video_pretrain.json:34)
  • Stage 2 vision_loss_weight = 0.5(configs/moe_fast_video.json:34)
  • β 调度(1.0 → 0.5)论文未披露

为什么是当前帧(V_t)而不是未来帧(V_{t+1})?

答案藏在序列构造本身 —— V_t 在 S_t 里自然出现在 A_{t-1} 之后、A_t 之前,模型天然需要"先生成当前图像、再生成当前动作"(causal mask 下)。让它预测当前帧相当于复用 VLM 的 next-token 结构,不需要改架构。若改为预测 V_{t+1},则需要重新设计条件注入逻辑。此外,VQ 离散化引入了硬信息瓶颈(32768 个码本条目),使当前帧预测已经不平凡,模型无法"复制输入"作弊。

2.3.2 Diffusion World Model(ViT 路径,§3.2 L54-L68)

ViT backbone 没有离散 visual 词表,next-token prediction 不再自然。作者改用 latent diffusion(代码实为 flow matching,见下):

  • 用预训练 VAE 编码未来帧 I_{t+1} 得到 latent z_{t+1}
  • 前向扩散把未来视觉 latent 加入高斯噪声；k 是随机 timestep
  • 去噪器以 VLA 输出 F_V 和 F_A 为条件,预测噪声残差:
LWD=E[∣ϵ−ϵ^(z,k,FV,FA)∣2]L^\mathrm{WD} = \mathbb{E}[\mid \epsilon - \hat{\epsilon}(z, k, F_V, F_A)\mid ^2]LWD=E[∣ϵ−ϵ^(z,k,FV​,FA​)∣2]

(其中 L_WD = L_WM-Diff,z = 加噪后 latent z_tk;这里把 latent 下标拆出来避免一条 equation 多下标劈碎)

联合优化:

Ltot=Lact+β⋅LWDL^\mathrm{tot} = L^\mathrm{act} + \beta \cdot L^\mathrm{WD}Ltot=Lact+β⋅LWD

Paper vs Code 关键差异:论文 Eq.4 写的是 DDPM 风格 || ε − ε̂ ||²,但代码 models/policy_head/flow_matching.py:39-63 实现的是 Flow Matching(Lipman 2023),target 是速度 (z₁ − x) 即 v_θ(z_t, t, cond) 的 MSE 对齐,不是 DDPM 的噪声预测。这是论文简化表述和代码实际实现的实质差异,复现时必须用 flow matching 版本。

为什么 ViT 必须预测未来帧(I_{t+1})?

作者在 §3.2 L56-L57 说得很清楚:"since the model is conditioned on all present features simultaneously, predicting the future is necessary to learn predictive dynamics rather than simply performing a reconstruction task."

翻译:如果预测的是当前帧,F_V 本身就是当前帧的编码,denoiser 可以通过简单 skip connection 复制条件达成重建,损失变 trivial。必须预测下一帧才会强迫模型学 F_A 与场景演化的因果耦合。

推理时:和 AR WM 一样彻底跳过 denoising,flow matching 只用于训练时提供梯度。

推理效率关键:VLA Expert 只算一次并 cache,真正的 action decoding loop 只在 AE 里迭代,所以才能从 117.8ms 降到 74.3ms。

§ 3. 数学推导与论据

3.1 核心公式独立推导(v9.6 BLOCKING)

推导 1:AR WM loss 是 VLA 在视觉 token 空间上的 MLE

前提:

  • P_theta(v_i | S, previous v) 是 VLM 在位置 i 输出的 softmax over 32768 码本
  • 真实 visual token v_i^* 来自 MoVQGAN 对真实图像 I_t 量化后的 token

推导:

  1. 最大化 log-likelihood:
θ∗=arg⁡max⁡θ∑i=1Nlog⁡Pθ(vi∗∣S<Vt,v<i∗)\theta^* = \arg\max_\theta \sum_{i=1}^{N} \log P_\theta(v_i^* \mid S_{<V_t}, v_{<i}^*)θ∗=argθmax​i=1∑N​logPθ​(vi∗​∣S<Vt​​,v<i∗​)
  1. 改写为最小化负 log-likelihood:
θ∗=arg⁡min⁡θ[−∑i=1Nlog⁡Pθ(vi∗∣S<Vt,v<i∗)]\theta^* = \arg\min_\theta \left[ -\sum_{i=1}^{N} \log P_\theta(v_i^* \mid S_{<V_t}, v_{<i}^*) \right]θ∗=argθmin​[−i=1∑N​logPθ​(vi∗​∣S<Vt​​,v<i∗​)]
  1. 这就是论文 Eq.2 的 L_WM-AR,和 Action 侧的 CE 损失结构完全同构,只是 vocab 不同(visual 32768 vs action FAST 2048)

关键观察(论文未强调):由于 V_t 在序列中紧跟 A_{t-1} 之前,v_{<i}^* 是前 i-1 个 ground truth visual token (teacher forcing),和 action autoregressive 训练完全对称。推理时跳过这部分,相当于把整段 V_t 视为"空位"直接进 action token 预测 —— 这就是为什么 WM 零推理开销。

推导 2:Flow Matching loss(代码实际)对比 DDPM simple loss(论文写)

论文 Eq.4 的 DDPM 风格写法(前提是 DDPM):

  • DDPM 前向:z_k = sqrt(ᾱ_k) · z_0 + sqrt(1 - ᾱ_k) · ε,eps ~ N(0,I)
  • 变分 ELBO 简化(Ho 2020):L_simple = E[||ε − ε̂(z_k, k, c)||²]
  • 代入 c = (F_V, F_A),z_0 = z_{t+1} 即得论文 Eq.4

代码实际 Flow Matching(Lipman 2023):

  • 前向路径:x_tau = (1 - tau) * x0 + tau * x1,其中 x0,x1 = z_next(目标)
  • target 是 velocity: u(x_τ, τ) = x_1 − x_0
  • loss: L_FM = E[||u(x_τ, τ) − v_θ(x_τ, τ, c)||²]

两者关系:Flow Matching 在 τ ∈ [0, 1] 上是广义的 ODE 形式,DDPM 是 SDE 特例。数学上 Flow Matching 可涵盖 DDPM(通过特定选择 x_τ 路径),但 velocity target 与 noise prediction target 不等价。

结论:论文为表达简洁用 DDPM 记法,代码为训练稳定/样本效率选 flow matching。复现时严格对齐代码版本,用 DDPM 实现会掉分。

推导 3:Joint Attention 输出与分别做 cross-attention 不等价

前提:标准多头 attention Attn(Q, K, V) = softmax(QK^T / sqrt(d)) V

Claim:令 Q = [Q_V; Q_A],K = [K_V; K_A],V = [V_V; V_A],则 Joint Attention 的输出 O = softmax(QK^T / sqrt(d)) V,拆回两部分 O_V = O[:n_V],O_A = O[n_V:] 后:

OV=softmax([QVKV⊤,QVKA⊤]d)⋅[VV;VA]O_V = \mathrm{softmax}\left(\frac{[Q_V K_V^\top, Q_V K_A^\top]}{\sqrt{d}}\right) \cdot [V_V; V_A]OV​=softmax(d​[QV​KV⊤​,QV​KA⊤​]​)⋅[VV​;VA​]

也就是说,O_V 的 softmax 是在 V 和 A 拼接后的 key 集合上做归一化,所以 V/A 的权重不是独立的 —— 这是 joint 比"先 self-attention 再 cross-attention"更紧耦合的根本原因。

推导失败标记:如果 QVK_A 的量级显著大于 QVK_V(例如 AE 的 hidden_dim 和 VLA 不同导致 key 尺度不一致),O_V 可能过度关注 AE tokens 而忽略自身上下文。论文对此未提任何 scale normalization 策略 —— 这是 v3 发现的潜在坑。Phase 3 代码验证:moe_experts.py:90-91 有 q_norm / k_norm LayerNorm,但VLA 和 AE 的 hidden_dim 相同(都 4096),所以 key 尺度问题不存在;真正的隐患在于 rope_theta 不同(1e6 vs 10000)导致的位置编码尺度差。

§ 7. 理论体系严肃反驳(≥5 条)

Q1:Scaling Law 声明是否严格成立?

作者:"world modeling amplifies the data scaling law"(§1 L25)。

反驳:

  • 真正 power-law 要求 log-log 线性,需 ≥4-5 个 scale 点(Kaplan 2020 / Dehghani 2023 都 ≥5)
  • 本文只有 3 个点(70k / 700k / 70M),画 log-linear 就声称 scaling law — iPad 历史 LEARNINGS 警告过
  • Table 3 VQ 在 700k 非单调,严格 scaling law 不允许
  • 建议:标题改 "World modeling 在 70M 尺度相对 action-only 有更强增益" 更严谨

Q2:Supervision Deficit 概念是否"事后贴标签"?

反驳:

  • 任何迁移学习/表征学习工作都能套"稀疏监督 → 加 aux task"故事
  • LAW(2024-06)已做同构工作(latent WM),只是换"latent"为"image"
  • 缺"消除 WM 后性能退回原点"的严格消融 — Table 3 "VQ Baseline" 是 action-only,但 backbone 未经 WM 初始化,不能严格证明 WM 是 causal 因素
  • 崩溃假设:若用 MAE pretrain 的 ViT + action-only,可能拿到和 +WM 相近提升

Q3:推理时完全丢弃 WM 的代价?

反驳:

  • 丢弃 WM 意味着推理时退化为纯 VLA,WM 的"反事实推理"能力在部署时失效
  • Fig.5 "减速指令下世界响应减速"是训练期可视化,生产推理根本不跑这块
  • 未来做 Model Predictive Control 闭环推理时,这个设计反而是阻碍

Q4:MoE Action Expert 是否真的是最佳 decoder 路径?

作者:AR 在大规模数据下最优,flow "sample-inefficient"。

反驳:

  • Phase 2 微卷的大白博客质疑:Flow Matching 专家实现过简,condition 只有 VLA 特征,对比 DiffusionDrive/DiffVLA 有 trajectory-level constraints
  • 70M 帧对 flow matching 是否"足够"?flow 文献典型数据量 1-10B tokens,并不一定"无法收敛",可能只是调参不够
  • AR 需要 FAST tokenizer 量化误差抵消,若有更好 tokenizer,flow 连续优势可能反超
  • 崩溃假设:若给 flow 专业调优 + EDM ODE solver + 20k+ warmup,AR 优势可能消失

Q5:单前视摄像头真的够用吗?

Phase 2 微卷的大白博客尖锐批评:引望(华为子公司)必有多摄像头+LiDAR 生产系统,单前视更像学术方案验证。

反驳:

  • NAVSIM 集中高速/主路,单前视在城市复杂路口可能失效
  • Table 1 竞品 DiffusionDrive/WoTE 已 88+ PDMS,本文 88.4 仅微升 0.1,统计显著性存疑
  • Table 2 NAVSIM v2:EPDMS 86.1 vs DiffusionDrive 84.5,但 EC(Extended Comfort)58.9 vs 87.7 大幅落后 — WM 在"舒适度"维度有盲点

§ 11. 结论与限制

11.1 本文真正的价值

  1. supervision deficit 命名 + 大规模实证:把行业隐约感觉的"VLA 用大模型小监督"问题明确命名,并在 70M 帧级别给出严格的 scaling 实验证据
  2. "WM 训练时用、推理时丢"的正则化范式:这是 VLA+WM 研究中第一次被完整证明可行的路线,为后续工作留出"训推分离"设计空间
  3. action decoder scaling 反转的意外发现:推翻社区对 flow matching / diffusion 的"未来属于复杂 decoder"舆论,为工业部署给出"大规模数据下用简单 AR"的指导

11.2 论文明确的局限(来自失败案例分析)

Failure process

失败链路:视频未来错了,轨迹会一致地跟着错

视觉预测偏差

世界模型误判动态物体或道路拓扑。

内部一致性仍成立

轨迹与预测视频保持一致,但一致的是错误未来。

规划行为失效

不必要停车、错误转向或错过潜在冲突。

  1. 指令模糊性:NAVSIM 离散指令集(Turn Left/Straight/Right)粒度过粗,复杂 Y 路口决策不确定
  2. 动态对象预测误差:WM 在复杂交叉口预测多动态对象(如对向来车)仍有挑战
  3. EC(Extended Comfort)指标偏低:NAVSIM v2 上 EC 58.9(DiffusionDrive 87.7),舒适度优化空间大

11.3 v3 独家发现的隐含问题

  1. AR inference GT action leak 嫌疑(Issue #5):可能使 AR PDMS 数字虚高,作者未澄清
  2. "数据 scaling law"声明严格性不足:仅 3 scale 点且 700k 非单调,不构成 power-law
  3. 大量"未披露但复现必需"参数(adaLN / CFG / Beta(1.5,1.0) / 256+8192 anchor / pre_action 等),独立复现难度高 → Issue #16 Qwen -16 PDMS 就是例证

11.4 未来方向

  • 更细粒度导航指令体系
  • 多视角输入扩展(当前仅单前视)
  • WM 的动态对象建模增强
  • 更大规模数据(>70M)下的持续 scaling 研究
  • 闭环 WM 推理模式(训练时也丢、推理时也用)

12.2 源码精读：动作编码、Flow Matching 与推理落盘

12.2.1 ActionTokenizer：连续轨迹如何变成语言模型 token

models/tokenizer/action_tokenizer.py:24-34 先在 [-1,1] 上均匀建立 256 个 bin，并把动作 token 放到词表尾部；:36-41 对动作 clip 后用 np.digitize 分箱，再用 last_vocab_idx - discretized_action 反向映射为 token id；:82-90 在反解码前处理边界，避免最后一个 digitize index 越过 bin_centers。

action = np.clip(action, -1, 1)
discretized_action = np.digitize(action, self.bins)
token_ids = self.last_vocab_idx - discretized_action

手算例子：假设归一化横向动作为 0.0，256 个端点从 -1 到 1，digitize 得到大约中间 bin；模型生成 token 后再反向查找 bin center，最后用场景的 action_low/action_high 做反归一化。该过程解释了为什么“动作 token 看似是文本”并不意味着语义词义：它只是把连续控制值借用到词表的稀疏尾部。

12.2.2 FlowMatching：训练目标与采样方向

models/policy_head/flow_matching.py:19-37 用 Uniform 或 Beta(1.5,1.0) 采样时间；:49-58 构造 z_t=(1-t)x+tε，令网络预测速度/残差并以 (ε-x-vθ)^2 做 MSE；:65-80 在采样时从噪声状态反向 Euler 更新，并可用 classifier-free guidance 合并条件与无条件速度场。

t = sample_t(batch)
z1 = torch.randn_like(x)
zt = (1 - t) * x + t * z1
vtheta = model(zt, t, cond)
loss = ((z1 - x - vtheta) ** 2).mean()

因此图中箭头必须从“数据动作/特征”指向“噪声端”的加噪训练路径，同时采样箭头从噪声端反向回到动作端；把训练和采样画成同一个方向会误导读者。

12.2.3 两种公开动作实现：共享层 Joint Attention 与独立 patch 网络

Pi0-style 共享层：reference/Emu3/emu3/mllm/modeling_emu3.py:1726-1923 对 VLM/Action 两路 Q/K/V 做联合注意力，并支持推理时缓存 VLM K/V。独立 patch 网络：models/policy_head/moe_experts.py:277-310 则把 B×C×H×W 张量 patchify，经时间/类别条件、decoder 和 FinalLayer 后 unpatchify。两者体现不同工程路径；图解与复现必须先确认 checkpoint/训练脚本实际实例化的是哪一个类，不能把 patchify/AdaLN 细节强行画入所有 Joint Attention 配置。

12.2.4 推理：输入、采样步数、反归一化、JSON

inference/vla/inference_action_navsim_flow_matching_vava.py:168-179 从配置读取采样步数，输入 input_ids、attention_mask、pre_action、cmd 并调用 model.sample_actions；:181-196 用 q01/q99 统计反归一化，按场景 token 名称写出 JSON。因而数据流图必须包含“归一化动作 → 采样 → 反归一化 → 结果文件”四个节点。
