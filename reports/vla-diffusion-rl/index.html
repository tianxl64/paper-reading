3. 问题与方法地图

本报告把自动驾驶VLA与具身VLA定义为两个核心应用子方向，因此各选四篇锚点；下表七个方法族是跨应用域的比较维度，而不是额外“核心子方向”。四个接口始终是观察编码、语言/任务注入、动作生成和控制接入。

继承关系：Diffusion Policy、π0、DiffusionDrive 和 GoalFlow 先建立连续多峰动作生成底座；Diffusion-QL、IDQL、DPPO、ReCogDrive 与 pi_RL 分别在训练损失、推理选样、生成内层转移或整段轨迹 reward 上继承该动作分布。分歧关系：各路线的根本分歧不是名称，而是最终动作密度是否可算、RL 是否在线、credit 落在物理时间还是生成时间、以及动作是 token 还是连续 chunk。组合关系：当前可复现组合通常是行为预训练 + 目标域适配 + reward/Q/advantage 更新 + BC/KL 锚定 + receding-horizon 闭环；这些模块可以组合，但证据必须按各自接口核算，不能把底座能力归因于 RL。

问题与假设

来源事实 条件状态为 B x To x Do，或 RGB 为 B x To x C x H x W。采样返回轨迹 B x Ta x Da 和保留的 chain B x (K_ft+1) x Ta x Da。PPO 采样 environment-step/denoising-step 对，并将梯度限制到 reward_horizon 动作位置。 [E1] [E2] [E3] [E4] [E5]
模型结构
来源事实 冻结的 base diffusion actor、fine-tuned actor 副本、标量 critic，以及可选的 learnable DDIM eta。外层 MDP 是物理环境；内层 MDP 是反向去噪 chain。 [E1] [E2] [E3] [E4] [E5]

来源事实 先用演示数据预训练，再在 Gym/D4RL kitchen、D3IL、Robomimic 和 Furniture-Bench 中进行在线向量化 rollout。state/image wrapper 对 observation/action 归一化，MultiStep 执行动作前缀并累加奖励。 [E1] [E2] [E3] [E4] [E5]
Loss各项与权重
来源事实 GAE 提供外层 step advantage。每个转移的 ratio 为 exp(mean(logp_new-logp_old))；依赖去噪步的 PPO clip 产生 max(-A*r,-A*clip(r))；critic 使用可选 clipped MSE。可选 BC 从冻结 teacher 采样 chain，并最大化其在当前策略下的概率。Approximate KL 用于监控/提前停止，而非 KL penalty。 [E1] [E2] [E3] [E4] [E5]
一次forward、推理与闭环
来源事实 VPGDiffusion.forward 采样高斯动作 tensor 并遍历 DDPM/DDIM。只有配置的最后 K_ft 个转移使用 fine-tuned actor；rollout 执行 output[:act_steps]。评估使用确定性采样，训练则保留探索噪声。 [E1] [E2] [E3] [E4] [E5]
控制/评测/指标
来源事实 基于向量化 rollout 评估 online return 和环境专用 success，涵盖像素输入、稀疏奖励、长时程家具组装，以及零样本 sim-to-real 家具迁移。成功阈值和奖励聚合因环境而异，必须保持任务局部定义。 [E1] [E2] [E3] [E4] [E5]
结果与四类泛化边界
综合判断 证据支持 BC 后由奖励驱动的执行与动力学鲁棒性，包括困难的稀疏/长时程设置。它并未证明语言或组合式 VLA 泛化。Sim-to-real 共同取决于 RL、模拟器保真度和 domain randomization。 [E1] [E2] [E3] [E4] [E5]
复现契约
综合判断 固定 cc7234a；保留 pretrained checkpoint、cfg、seeds、n_envs、n_steps、act_steps、horizon_steps、DDPM/DDIM schedule、K_ft、最小 sampling/logprob std、reward scaling、gamma/lambda、clip schedule、update epochs、target KL 和 success threshold。保存解析后的 Hydra config 和 result.pkl。 [E1] [E2] [E3] [E4] [E5]

综合判断 DPPO 与 baseline 必须使用相同 BC checkpoint、environment seeds、interaction steps、reward、action chunk、actor backbone 和 evaluation protocol。分别统计环境交互与去噪计算。 [E1] [E2] [E3] [E4] [E5]

综合判断 必需项：仅 BC；Gaussian PPO；K_ft 和 denoising discount；DDPM 对 DDIM/eta；exploration/logprob std；reward_horizon；可选 BC coefficient；clip schedule；critic warmup；像素 observation 对 state；matched-compute 比较。 [E1] [E2] [E3] [E4] [E5]

  2. 综合判断 保留演示初始化，同时直接优化闭环 return。
  3. 综合判断 官方代码覆盖多种环境、state/image policy 及完整训练/评估循环。

8.2 新生成 QA：基础

基础1. Diffusion Policy 为什么适合机器人和驾驶轨迹？
因为条件动作分布常多峰：绕左或绕右、抓取姿态A或B都合理。单高斯回归易输出两种模式的均值，可能物理无效；diffusion/flow能保留多个mode，并一次生成时间一致的chunk。但表达力不自动等于闭环优越，仍受示范覆盖、采样延迟和selector影响。
基础2. π0 是 diffusion 还是 flow matching？
更严格地说是conditional flow matching VLA。它学习连续向量场并用ODE Euler积分生成动作。它和DDPM共享“从噪声到动作”的生成直觉，但训练目标、采样器和likelihood处理不同。
基础3. 使用了 reward guidance 就算 RL 吗？
不一定。Diffusion Planner在推理时用可微energy引导采样，但没有用return更新policy参数，因此本报告归为guided generation而非RL。RL要求reward/Q/advantage引起显式policy improvement。
基础4. Action chunk 为什么能提高控制频率？
它不是让大模型本身更快，而是一次生成H步后由轻量runtime逐步消费，从而让servo loop高频运行。代价是chunk执行期间策略可能看不到新扰动，所以要同时报告H、实际执行步数和replan Hz。
基础5. 自动驾驶 VLA 的动作是方向盘油门吗？
多数论文不是。常见输出是未来ego waypoints、局部位姿增量token或文本坐标，再由LQR/PID/车辆控制器转成steer/throttle/brake。若论文没追踪到控制接口，就不能称其已证明低层闭环能力。
基础6. 为什么 open-loop L2/ADE 不够？
日志回放中其他参与者不会响应ego动作，模型还可能靠历史轨迹shortcut取得好分数。真实闭环中一个早期偏差会改变后续观测与交互，因此要用reactive simulator或真机/真车的成功、安全、舒适和恢复指标。
基础7. VLA 的语言输入在每个控制tick都变化吗？
通常不是。语言更像episode/task条件，视觉和proprioception高频变化。工程上常缓存语言/图像prefix或让高层VLM低频运行，再由action expert/chunk完成高频控制。
基础8. RL 会自动提升视觉泛化吗？
现有最明确的RL4VLA证据显示视觉shift上RL通常只与SFT相当，而执行/动力学shift提升显著。RL优化状态访问和错误恢复，不会凭空增加视觉域不变特征。

8.3 新生成 QA：进阶

进阶9. DPPO 为什么不直接计算最终action的log-prob？
隐式diffusion终点密度难解。DPPO把每个reverse Gaussian transition当成内层动作，transition log-density可计算，于是用路径old/new log-prob做PPO。这优化的是生成路径概率，不是硬算终点density。
进阶10. Diffusion-QL 和 IDQL 的本质差异？
Diffusion-QL让Q梯度进入actor loss，训练时改变分布；IDQL保持behavior diffusion不变，推理时用critic从多个候选中重采样。前者可能离开支持集且受Q外推影响，后者更稳但候选成本高、上限受behavior支持。
进阶11. ReCogDrive 的 DiffGRPO 与语言模型 GRPO 有何差别？
action是连续diffusion trajectory，policy ratio累积在reverse transitions；reward来自完整轨迹PDMS，并对早期高噪step折扣，还混合BC稳定。语言GRPO通常在AR token log-prob上操作，时间轴与分布形式不同。
进阶12. 为什么同一 advantage 复制给所有去噪步可能有偏？
早期去噪主要决定粗mode，后期决定细节；它们对最终return的边际贡献不同。把物理trajectory advantage等权复制会忽略生成时间的credit结构，可能让噪声最大的step获得过强梯度。折扣或只微调末步是实用近似，不是无偏定理。
进阶13. DiffusionDriveV2 为什么要 anchor 内分组？
不同anchor代表不同驾驶意图，绝对reward均值不同。普通GRPO跨mode标准化可能让高均值mode消灭稀有但合法mode。anchor内比较保留多模态；但也可能削弱跨mode绝对质量校准，且最终selector仍需单独学习。
进阶14. Flow ODE 没有显式likelihood，π_RL怎么做PPO？
它提出Flow-Noise，把生成建成带可算transition likelihood的离散MDP；或Flow-SDE，把ODE随机化为SDE形成两层MDP。FPO++另走CFM loss-difference surrogate，较简洁但不是exact likelihood ratio。
进阶15. 为什么 reward 里加可行性仍不等于安全？
可行驶区、曲率、碰撞代理只覆盖部分风险，而且simulator和signed-distance field可能有盲点。FeaXDrive说明单PDMS会鼓励高曲率，但加入约束只能证明对该proxy更稳，不能替代真实反事实交互和安全壳。
进阶16. OpenPI 的论文公式和代码为什么方向相反？
论文常把τ=0记为噪声、τ=1记为数据；当前代码把t=1记为噪声、t=0记为数据，并以负dt积分。路径方向等价，只是变量替换。源码第226–227行明确说明该约定。

8.4 新生成 QA：研究级

研究级17. 如何公平比较AR token、diffusion和flow action head？
必须固定感知backbone、训练数据、初始化、action horizon/维度、控制器、replan Hz、硬件和闭环任务；同时报告质量、mode coverage、P95 latency、恢复和安全。否则差异可能主要来自数据或评测设置。
研究级18. 如何检测critic把diffusion sampler推到OOD伪高值动作？
同时测behavior log-density/typicality、ensemble Q分歧、calibration on held-out rollouts、动作动力学残差与真实rollout return；对Q-guided动作做nearest-demonstration和counterfactual扰动。只看Q值会上当。
研究级19. GRPO动态丢弃全成/全败组有什么统计后果？
它提高非零advantage样本比例，却把训练分布偏向中等难度任务；极难任务可能永久得不到梯度。应报告每task采样与丢弃率、worst-tail成功率，并考虑难度加权保留全败组。
研究级20. 怎样区分RL提升来自探索还是更多环境数据？
设等量online data的SFT/DAgger/replay对照，固定初始化和采样状态分布；记录新状态覆盖、行为熵、失败恢复路径和回报。若仅把成功rollout再SFT也获得相同提升，就不能把增益全归因于policy gradient。
研究级21. WAM-Diff 的统一 token space 如何验证不是“格式统一”？
做action-conditioned future prediction、counterfactual action swap、未来token干预与闭环planning ablation；检查world token是否对不同动作产生可校准未来，并能改善控制。若只联合生成但不支持反事实，统一主要是接口层。
研究级22. 如何设计跨本体动力学泛化评测？
固定任务语义与视觉，系统改变控制频率、延迟、关节/车辆参数、payload、摩擦和actuator saturation；分开报告零样本、少量适配和在线RL后的恢复。不要把新相机外观混进动力学shift。
研究级23. 什么证据能证明 action chunk 的RL credit assignment正确？
逐位置mask或重采样chunk中的动作，估计每步对return的边际影响；对比逐步advantage、整chunk advantage与生成step advantage；检查梯度集中位置是否与counterfactual贡献一致。最终成功率不足以验证credit机制。
研究级24. 该方向最有价值的下一篇论文应解决什么？
在同一开放系统中统一报告：可复现的多域BC底座、精确或经校准的flow/diffusion policy ratio、长时闭环credit、约束/安全shield、四类泛化、P95端到端延迟、sim-to-real与失败录像。单一benchmark SOTA的边际研究价值已较低。

10. 综合判断、完成问题与学习路线

10.1 八个完成问题的明确回答

  1. 解决什么问题？在多峰连续控制中保持时间一致性，并利用闭环reward修正示范偏差；方法族按生成底座、Q引导、critic选样、生成内层MDP、序列group RL、token RL和加权回归划分。
  2. 为何设计不同？最终action density是否可算、是否有在线环境、动作是token还是continuous chunk、reward是否只在终点可得，共同决定接口。
  3. 本质差异？观察与语言条件位置、动作空间、监督目标、生成时间、实际执行前缀和环境反馈粒度不同。
  4. 性能差异来自哪里？矩阵B显示数据规模、预训练、参数/算力、本体、控制器和评测口径是主要混杂；跨论文数字多数不可直接比较。
  5. 代码如何实现？OpenPI给出flow-VLA底座；DPPO给出reverse transition log-prob、GAE、clipped ratio、BC anchor与更新的完整实现。
  6. 证据等级？所有矩阵cell和锚点claim都显式标为来源事实、综合判断、未报告或实验假设。
  7. 关键失败与实验？三时间轴credit错位、proxy hacking、critic外推、mode collapse、task starvation和chunk迟钝；九字段实验见第7章。
  8. 下一步？先复现Diffusion Policy/OpenPI的action contract，再审计DPPO update链，最后做chunk扰动、anchor遗忘和proxy-to-reactive三项实验。
